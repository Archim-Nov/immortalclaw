# 九州与事件规划

## 目的

本文件负责把 P1 的 `游` 模块从“概念上的九州”整理成可配置的世界数据框架。

重点不是给每州写长篇故事，而是给实现提供稳定结构。

## 九州冻结名单

P1 直接采用完整九州：

- 青州
- 扬州
- 中州
- 蜀州
- 幽州
- 凉州
- 雷州
- 沧州
- 宛州

## 每州固定拓扑

每州统一采用同一套最小结构：

- `1 个州主城`
- `3 个州辅镇`
- `1 个州外游历区`
- `3 个副本 / 高风险节点`

建议命名模板：

- 州主城：`<州名>仙城`
- 州辅镇：`辅镇 A / 辅镇 B / 辅镇 C` 或后续确认命名
- 州外游历区：`<州名>州外山野`
- 副本节点：`丙级节点 / 乙级节点 / 甲级节点` 的层级占位名

说明：

- 当前冻结的是 `节点类型和层级`
- 当前不冻结的是 `最终文案命名`

## 州模板字段

每州至少配置以下字段：

- `stateId`
- `stateName`
- `mainCity`
- `subTowns`
- `wildZone`
- `dungeons`
- `resourceBias`
- `riskBias`
- `travelTags`
- `eventBias`
- `sectHooks`
- `specialRule`

## 九州差异方向

P1 不要求九州一上来就做复杂规则差异，但每州至少要有清晰的资源倾向和事件方向。

| 州 | 主倾向 | 主资源方向 | 主风险方向 | 组织 / 势力钩子 |
| --- | --- | --- | --- | --- |
| 青州 | 新手与均衡 | 药材、基础灵石 | 低风险、低阶妖患 | 低门槛组织接口 |
| 扬州 | 水路与贸易 | 水属性材料、跑商收益 | 水域赶路事件 | 市井与商会接口 |
| 中州 | 中枢与秩序 | 综合资源、宗门联络 | 官面任务与巡查 | 组织事务中转接口 |
| 蜀州 | 山地与灵植 | 药草、灵木 | 山路耗时、隐秘事件 | 恢复 / 采药向组织接口 |
| 幽州 | 边境与寒地 | 寒性材料、狩猎收益 | 中风险野外遭遇 | 巡防与镇压接口 |
| 凉州 | 戈壁与矿脉 | 矿材、妖核 | 长途赶路、枯竭压力 | 资源上缴接口 |
| 雷州 | 异象与爆发 | 雷性碎片、强事件线索 | 状态型事件偏多 | 高风险事务接口 |
| 沧州 | 海贸与遗迹 | 水灵材、残碑碎片 | 航路事件、遗迹事件 | 调查与遗迹事务接口 |
| 宛州 | 人情与江湖 | 杂项资源、关系事件 | 邪修与流寇事件 | 人情与联络接口 |

说明：

- 这里的“组织 / 势力钩子”只描述玩法职能
- 不等于已经冻结具体宗门名单或流派设定

## 节点功能分工

### 1. 州主城

固定承接：

- 主任务板
- 主交易入口
- 宗门入口
- 跨州信息入口

### 2. 州辅镇

固定承接：

- 地方任务板
- 地方资源委托
- 轻交易入口
- 区域消息入口

### 3. 州外游历区

固定承接：

- 州内默认游历
- 州特有事件池
- 轻遭遇与强事件前置

### 4. 副本节点

固定承接：

- `丙等`：P1 首个副本接触层
- `乙等`：中压内容
- `甲等`：P1 顶格单人高风险入口

## 风险分层

P1 风险统一采用：

- `safe`
- `low`
- `medium`
- `high`

节点默认风险：

| 节点 | 默认风险 |
| --- | --- |
| 州主城 | safe |
| 州辅镇 | safe / low |
| 州外游历区 | low / medium |
| 丙等副本 | medium |
| 乙等副本 | medium / high |
| 甲等副本 | high |

## 赶路规则

### 1. 州内移动

建议耗时：

- `主城 -> 辅镇`：`1 tick`
- `主城 -> 州外游历区`：`2 ticks`
- `辅镇 -> 州外游历区`：`1-2 ticks`
- `同州副本节点`：`2-3 ticks`

### 2. 跨州移动

建议耗时按距离档处理：

- 相邻州：`4 ticks`
- 中距离州：`6 ticks`
- 远距离州：`8 ticks`

### 3. 统一公式口径

P1 直接采用以下公式结构：

`最终赶路耗时 = 基础距离耗时 + 地形修正 - 移动能力修正 + 状态修正`

P1 先冻结结构，不追求复杂小数级调优。

## 事件池结构

### 1. 事件来源

P1 只先做两个来源：

- `exploration`
- `travel`

### 2. 事件语义类型

P1 统一沿用三类：

- `fortune`
- `training`
- `human`

### 3. 事件结果模板

P1 统一沿用五类：

- `resource`
- `progression`
- `status`
- `combat`
- `story`

### 4. 事件池分层

P1 统一采用四层结构：

- `global-common`
- `state-specific`
- `node-specific`
- `special-overlay`

## P1 事件最低容量

### 1. 全局通用游历池

- `fortune` 5 条
- `training` 5 条
- `human` 5 条

合计至少 `15 条`

### 2. 每州特有游历池

每州至少：

- `fortune` 3 条
- `training` 3 条
- `human` 3 条

九州合计至少 `81 条`

### 3. 通用赶路事件池

- `fortune` 3 条
- `training` 3 条
- `human` 3 条

合计至少 `9 条`

### 4. 节点覆盖池

每州建议至少：

- 州外游历区 `1-3 条` 专属覆盖事件
- 甲等副本 `1-2 条` 专属覆盖事件

## P1 事件抽取规则

当前在本规划包中补充冻结为：

1. 每次 `游历` 或 `赶路` 先抽 `1 个主事件`
2. 若主事件结果不是 `combat`，则有 `30%` 概率追加 `1 个 story 次事件`
3. 若主事件结果为 `combat`，本次不再追加次事件
4. 次事件只允许产生日志、线索、轻关系变化，不允许覆盖主事件结算

这样做的原因：

- 保持实现简单
- 保留一定世界烟火气
- 避免一次动作同时爆出太多系统结果

## special-overlay 在 P1 的实现口径

P1 先只要求支持以下三类 overlay：

- `recoveryState overlay`
- `sect-affiliation overlay`
- `dominant-element overlay`

解释：

- `recoveryState overlay` 负责让伤势和枯竭影响事件权重
- `sect-affiliation overlay` 负责把游历重新解释为组织化事务
- `dominant-element overlay` 负责把角色的五行偏向接进内容推荐和少量掉落偏好

P1 不要求：

- 复杂天气 overlay
- 多派系 overlay
- 深度阵营 overlay

## 州模板验收清单

- 每州都有主城、3 辅镇、州外游历区和 3 个副本节点。
- 每州都有资源倾向、风险倾向和宗门钩子。
- 州内移动和跨州移动都需要时间。
- 州外游历区是默认游历位置，不是城镇。
- 事件池具备最小容量，而不是只有空结构。
