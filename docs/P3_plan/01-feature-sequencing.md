# P3 功能排序

## 目的

本文件用于把 `00-scope-freeze.md` 中已经冻结的 `P3` 方向，拆成一条可执行的工作包顺序。

这里的“排序”可以简单理解成：

- 哪部分先做
- 哪部分要建立在前面的结果上
- 哪部分最容易把 `P3` 重新拖成无限扩张

## 排序原则

### 1. 先补终局地层，再补高光组织层

如果 `八荒` 和 `归墟` 还没立住，`阵营战` 和 `宗门等级` 容易失去真正的空间承接层。

### 2. 先把多人高光战斗做实，再谈高强度组织冲突

阵营战和宗门高光一定要建立在更稳的多人协作战斗之上。

### 3. 社交与战斗扩展放在收尾增强，而不是主轴起点

`P3` 中更完整的社交与战斗扩展应该补强终局体验，而不是反客为主变成一轮新的大系统开题。

### 4. 明确排除项持续有效

即使进入 `P3`，那些不在当前路线内的大系统仍然不自动解禁。

## P3 工作包总览

当前建议按 6 个工作包推进：

1. `P3-0` P2 收口确认门
2. `P3-1` 八荒完成
3. `P3-2` 归墟接入
4. `P3-3` 多人高光战斗完成
5. `P3-4` 阵营战与宗门等级
6. `P3-5` 社交 / 战斗收尾增强与最终收口

## `P3-0` P2 收口确认门

### 目标

在正式进入 `P3` 前，先确认 `P2` 的主轴已经成立。

### 本包应覆盖

- 确认 `P2` 的高风险成长循环稳定成立
- 确认 `P2` 的生产队列、轻社交、宗门轻进阶已接回主循环
- 确认 `P2` 不再依赖旧污染项

### 为什么它必须先做

如果 `P2` 还没真正站稳，`P3` 很容易退化成“边做终局、边补中层漏洞”。

## `P3-1` 八荒完成

### 目标

把 `P2` 触达的 `八荒` 扩展层，补成真正成立的高风险远征层。

### 本包应覆盖

- 更完整的八荒区域结构
- 门票、限时生存、撤离逻辑的完成版
- 八荒专属极端事件池
- 八荒高价值掉落与高压后果

### 为什么它排在归墟前面

因为 `归墟` 是终局层，而 `八荒` 是从中高压走向终局的桥。

## `P3-2` 归墟接入

### 目标

让 `归墟` 正式成为终局节点开拓层。

### 本包应覆盖

- 归墟节点结构
- 终局目标与推进方式
- 归墟专属事件与守卫内容
- 更明显的终局唯一性或共享性表达

### 为什么它排在多人高光战斗前

因为多人高光战斗的内容承接，需要先知道最终战场和最终目标是什么。

## `P3-3` 多人高光战斗完成

### 目标

把 `P2` 的组队副本雏形补成更完整的多人高光战斗层。

### 本包应覆盖

- 更完整的组队副本
- 更复杂的 Boss 压力与多人协作机制
- 更清晰的队伍构筑价值
- 继续复用统一战斗底层

### 为什么它排在阵营战前

因为阵营战是更高层的组织高光，如果多人协作战斗本身还没成熟，阵营战只会更难收口。

## `P3-4` 阵营战与宗门等级

### 目标

让 `势` 从 `P2` 的轻进阶层，升级为真正的组织高光层。

### 本包应覆盖

- 同州阵营战
- 宗门积分
- 宗门等级
- 全员加成
- 更强组织目标

### 为什么它排在社交收尾增强前

因为这是 `P3` 最明确的高光组织主线，优先级高于额外润色。

## `P3-5` 社交 / 战斗收尾增强与最终收口

### 目标

在前面几包已经成立的前提下，补齐更完整的社交与战斗延展，并完成当前路线收尾。

### 本包应覆盖

- 比 `P2` 更深一层的私域社交黏性
- 与终局内容更紧密的关系 / 协作表达
- 最终战斗表现层和日志表现层收口
- 最终文档、目标、推荐口径统一

### 当前边界

这一包做的是“收尾增强”，不是“新大系统开题”。

因此它不应包含：

- 完整道侣并网系统
- 完整多人职业体系
- 完整法宝 / 阵法 / 灵兽 / 伴生体 / 装备词条大系统

## 推荐执行顺序

当前正式推荐顺序如下：

1. `P3-0` P2 收口确认门
2. `P3-1` 八荒完成
3. `P3-2` 归墟接入
4. `P3-3` 多人高光战斗完成
5. `P3-4` 阵营战与宗门等级
6. `P3-5` 社交 / 战斗收尾增强与最终收口

## 不建议的错误顺序

### 1. 先做阵营战

问题：

- 容易让组织高光层失去足够成熟的地图层和战斗层支撑

### 2. 先做归墟，再补八荒

问题：

- 终局层会缺少中间桥梁
- 版本节奏会显得跳跃

### 3. 先做收尾增强，再补主轴

问题：

- 容易把 `P3` 做成一堆润色，而不是完整收尾

### 4. 在 `P3` 中重新引入不在路线里的大系统

问题：

- 会让 `P3` 失去终点
- 会让当前路线重新变成开放式膨胀

## 当前冻结结论

- `P3` 必须按工作包推进，而不是并行发散
- `P3-0 -> P3-5` 是当前建议的正式顺序
- `P3` 的目标是完成当前路线收尾，不是继续横向扩张
- 那些已明确排除的大系统，不因进入 `P3` 而自动解禁
