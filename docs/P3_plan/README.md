# P3 规划总包

## 目的

本目录用于承接 `P2` 之后的第三阶段执行规划。

它的职责不是再开一轮无边界扩张，而是把当前 `P1 -> P2 -> P3` 路线中的最后一段补完整，形成一个能作为“当前路线收尾版本”的终局与高光规划包。

简单说：

- `P1` 让世界活起来
- `P2` 让高风险成长循环成立
- `P3` 让终局、高光和收尾成立

## 使用原则

### 1. source of truth 顺序

`P3` 规划包默认按以下顺序解释冲突：

1. `docs/specs/clawcity-gameplay-alignment/spec.md`
2. `docs/specs/gameplay-build-foundation/spec.md`
3. `docs/specs/gameplay-build-foundation/event-pool-foundation.md`
4. `docs/specs/combat-gameplay-v1/spec.md`
5. `docs/P1_plan/`
6. `docs/P2_plan/`
7. 本目录中的 `P3` 细化规划文档

### 2. P3 与 P2 的关系

- `P3` 不是重新定义玩法骨架
- `P3` 默认建立在 `P2` 主轴已经成立的前提上
- `P3` 的任务是把终局层、组织高光层和更完整的多人 / 社交延展层收束成当前路线的最终版本

### 3. 当前 P3 的启动原则

本目录当前采用以下启动口径：

- 先明确 `P3` 的终局边界
- 再明确 `P3` 的落地顺序
- 最后明确 `P3` 的收尾条件

这里尤其要避免两种错误：

- 把所有远期想象都塞进 `P3`
- 把 `P3` 写成没有终点的持续膨胀路线

### 4. 当前 P3 应优先回答的问题

在开始正式写 `P3` 细化内容前，优先确认：

- 哪些内容是当前路线里真正剩下的终局部分
- 哪些内容属于更完整的高光版本，而不是新系统开题
- 哪些曾在文档里出现过，但并不属于当前 `P1-P3` 路线
- 什么条件下可以宣布 `P3` 已经构成当前路线的收尾版本

## 目录说明

建议本目录至少包含：

- `00-scope-freeze.md`
  P3 的终局范围、边界和主目标。
- `01-feature-sequencing.md`
  P3 的工作包顺序与前后依赖。
- `02-closure-criteria.md`
  P3 作为当前路线收尾版本的验收标准与明确排除项。

当前已经建立：

- `00-scope-freeze.md`
- `01-feature-sequencing.md`
- `02-closure-criteria.md`

## 后续维护规则

- 若某项内容不在当前 `P1-P3` 路线内，不因“曾在旧草稿里出现过”而自动写入 `P3`
- 若某项内容属于终局与高光闭环，优先写进 `00-scope-freeze.md`
- 若某项内容属于执行顺序问题，优先写进 `01-feature-sequencing.md`
- 若某项内容涉及“算不算当前路线收尾”，优先写进 `02-closure-criteria.md`
- 不把“当前路线收尾项”和“未来也许会做的大系统”混写在同一条正文里
