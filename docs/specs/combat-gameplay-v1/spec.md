# 首版可落地战斗玩法规格

## Summary

本规格用于补齐 Immortal Claw 新玩法方案中的战斗总纲。它在 `ClawCity` 的 action-first 骨架之上，整合现有的入界登记、状态、属性、五行、兵器与境界文档，冻结一版能够直接指导实现的首版战斗玩法：`异步发起 -> 按 world tick 推演战斗轮次 -> 状态/掉落/日志回写 -> 重新进入世界循环`。

## Problem

- 外部玩法草案已经拆出了 `游 / 居 / 遇 / 势` 等章节，但缺少一份统一的战斗章节把这些系统串起来。
- 仓库里已经存在 `registration`、`attributes`、`five-element status`、`weapon foundation` 等专项文档，但尚未合成一份可直接落地的战斗规格。
- 当前原型中的战斗仍以单次 `power vs threat` 判定为主，难以承载后续的兵器、五行状态、组队副本与宗门冲突。

## Goals

- 明确战斗仍然是 `action 驱动` 的世界行为，而不是独立于世界状态的小游戏。
- 让 `registration_record`、8 个主属性、15 个详细属性、五行状态与兵器路线共同进入同一战斗结算框架。
- 冻结一版 `首版可实现` 的战斗状态模型、关键公式、内容入口、奖励与失败成本。
- 让战斗系统可以从当前 `packages/domain` 原型平滑升级，而不是推翻现有状态接口。
- 为后续 `组队副本`、`阵营战`、`宗门战` 预留统一底层，而不要求首版一次做完所有重系统。

## Non-Goals

- 不做即时手操或帧同步动作战斗。
- 不做 20 种兵器各自完整独立的招式树。
- 不做首版完整宗门战争赛季系统。
- 不做完整阵法、灵兽、法宝、伴生体与装备词条大系统。
- 不让战斗面板反客为主，取代主循环中的状态、行动与日志骨架。

## User-Visible Behavior

- 玩家在可战斗区域查看状态时，可以看到战斗准备度、战斗侧关键属性、主兵器家族、主五行倾向与当前战斗相关状态。
- 玩家发起战斗行动后，系统创建一个限时 action job，并在若干 `world tick` 内完成一场以 `1 tick = 1 战斗轮` 推演的规则战斗结算。
- 战斗结果会同步写回气血/灵力消耗、伤势、状态、战利品、修为推进与战斗日志。
- 入界登记带来的心性、行事相、动机与灵根只改变战斗风格和风险偏好，不制造注册阶段的绝对强度碾压。
- 首版以 `单人 PVE` 为主，统一底层后再向 `组队副本`、`异步 PvP` 与 `宗门阵营战` 扩展。

## Constraints

- 优先遵循 `docs/specs/clawcity-gameplay-alignment/spec.md`：战斗必须服务于世界动作骨架，而不是脱离世界独立存在。
- 优先兼容当前的 `CultivatorStateView`、`currentJob`、`combatLogs` 与现有 action 入口。
- 战斗逻辑必须以稳定 ID 为判断依据，不得重新回退到基于中文标签字符串的运行时分支。
- 第一版数值采用线性、可解释、便于调试的规则；复杂乘区、硬反应与套装联动延后。

## V1 实现边界（2026-04-04 冻结：light-complete）

本 spec 继续保留完整战斗蓝图，但当前仓库真正进入实现的，是一个更小、更稳、更便于调试的战斗 V1 子集。若正文后续章节提到更完整的控制、状态附着、五行战斗内结算或更大规模的动作扩展，均视为后续扩展目标，而不是本轮的必做项。

### 当前真正进入实现的内容

- `action-first` 战斗入口，继续通过现有 action 发起战斗
- `combat job` 状态机，战斗在 job 内部按 tick 推进，而不是一次性 `power vs threat`
- `1 world tick = 1 战斗轮`
- 当前 V1 的硬回合上限：
  - `hunt-mine-beast`：`5` 回合
  - `challenge-guardian`：`7` 回合
- 当前 V1 战斗决策分为两层：
  - **当前 V1 动作层 (Action Layer)**:
    - `普通攻击` (basic_attack)：基线伤害动作，倍率 1.0，无消耗。
    - `核心技` (core_skill)：高价值伤害动作，倍率 1.6，消耗固定 `coreSkillSpiritCost`（由装配层配置表提供，V2 装配层替代了早期的 `10% 最大灵力` 规则，参见 `docs/plans/2026-04-05-combat-gameplay-v2.md` 及 `docs/plans/2026-04-05-combat-gameplay-v2-gap-closure.md`）。
    - `逃跑` (escape)：非伤害动作，仅限玩家侧，成功则结束战斗（记为战败/撤退）。
  - **当前 V1 路线层 (Route Layer)**:
    - `蛮力` (brute)：正面压制，对应兵魄。
    - `巧劲` (finesse)：轻灵抢位，对应身法。
    - `战术` (tactic)：算路反制，对应道心。
- 服务端本地评分选路，不让 agent 参与逐 tick 选招
- 当前只实现 3 条路线：`蛮力 / 巧劲 / 战术`
- 当前默认只走 `兵器` 通道，`法术` 通道先保留接口
- **新增本轮：速度 / 先手判定、命中 / 闪避判定、会心 / 暴伤判定**
- 伤害模型：`底盘伤害 × 路线主属性系数 × 克制系数 × 命中修正 × 会心修正`
- 先手公式冻结为：`速度 + 准备度修正 + 路线修正 + 小随机`（不再包含上轮节奏链和伏击反伏击）
- 可读的战斗日志，能解释每回合伤害来源、先手判定、命中/闪避、会心与最终胜败原因


### 当前明确延后的内容

- `控制 / 状态附着`
- `五行` 的战斗内结算与元素状态互动
- 复杂技能树与完整资源博弈
- `防御 / 调息`、`重招 / 大术` 等额外动作层扩展
- 完整兵器家族实现与 `18` 把兵器细分
- `组队副本 / PvP / 宗门战`

### 文档优先级

- 总方向、长期设计边界与扩展目标，以本 spec 为准
- 当前 V1 的实现边界、精确公式、接口冻结和任务拆解，以以下两份 `2026-04-04` 计划共同为准：
  - `docs/plans/2026-04-04-combat-gameplay-v1-light-complete-implementation.md`
  - `docs/plans/2026-04-04-combat-gameplay-v1-action-layer-completion.md`
- 若本 spec 后续章节与 V1 详细计划存在冲突，以“当前实现边界”与 V1 详细计划为准

### 过渡说明

- 本 spec 中保留的完整多层战斗机制，继续作为后续版本的设计来源，不在本轮删除
- 角色面板中的 `8 个主属性 + 15 个详细属性 + 5 个五行属性` 仍保留为总设计结构，但当前 V1 战斗轮只直接消费攻防底盘、三路线主属性系数与克制系数
- `悟性` 在当前 V1 最小伤害结算中不直接参与伤害公式，保留给后续功法成长、术法精修与复杂技能系统
- 当前 V1 在到达回合上限后会自动结束战斗，并按双方剩余生命比例结算胜负；若生命比例相同，则按玩家失败处理，避免无成本拖回合

### V1 接口冻结

- `CultivatorStateView` 新增 `combatProfile`
- `combatProfile` 至少包含：
  - `battleReadiness`

  - `coreCombatStats`
  - `combatTraits`
- `CombatLogEntry` 从单条结果摘要扩展为“总结 + rounds”
- 当前 V1 需要的稳定内部类型至少包括：
  - `CombatStyle = "brute" | "finesse" | "tactic"`
  - `AttackChannel = "weapon" | "spell"`
  - `CombatSnapshot`
  - `CombatJobState`
  - `CombatRoundLog`
  - `CombatDamageBreakdown`
  - `EncounterTemplate`

## Requirements

### 1. 战斗状态与入口

- 顶层角色状态继续保持 `idle | busy | injured`，第一版不新增第四种全局状态枚举。
- 在状态视图中新增 `combatProfile` 这一派生视图，至少包含：
  - `battleReadiness`
  - `attackChannel`
  - `combatTraits`
  - `coreCombatStats`
- `weaponFamily` 与 `dominantElements` 保留为后续扩展字段，不作为当前 V1 的最小实现要求。
- 第一版强制保留 action-first 入口：玩家只能通过动作进入战斗，不能直接在空面板里“开打”。
- 首版必须支持以下战斗入口：
  - `hunt-mine-beast`
  - `challenge-guardian`
  - 与副本 / 阵营共享的通用遭遇模板
- 组队副本与宗门阵营战可以在后续阶段开放，但必须复用同一结算底层。

#### 1.1 `battleReadiness` 的首版定义

`battleReadiness` 当前冻结为前台可读的 4 档结论：

- `poor`：伤势重、灵力空、负面状态多，不建议进入高压战斗
- `stable`：可以打普通遭遇，但不适合连续高压内容
- `ready`：适合主动发起挑战
- `advantaged`：当前有明显有利状态，适合冲更高收益内容

首版要求：

- 前台必须直接展示结论，而不是要求玩家自行心算
- `battleReadiness` 是派生视图，不是新的顶层状态枚举
- 该字段主要服务于“能不能打、适不适合打、推荐打什么”

#### 1.2 战斗发起前置条件

所有战斗动作在创建 action job 前，至少检查以下条件：

- 当前所在区域是否允许该战斗入口
- 角色是否处于 `injured` 且超过当前内容的容忍阈值
- 气血与灵力是否达到最低发起标准
- 是否存在禁止战斗的剧情 / 场域 / 状态效果
- 当前是否已有互斥中的 job 正在执行

首版实现口径：

- 前置检查失败时，不创建战斗 job
- 返回明确失败原因，供状态面板和日志直接展示
- 不做“勉强开战后再立即强退”的隐式流程

#### 1.3 战斗时间基准

当前战斗时间模型正式冻结为：

- `1 world tick = 30 秒`
- `1 战斗轮 = 1 world tick`
- 首版不再为战斗额外拆分更细的实时 slice
- 战斗 job 在外层仍然是 timed action，在内层按每个 world tick 推演 1 个战斗轮次

这样做的原因是：

- 降低服务器压力与结算复杂度
- 保持战斗与世界时间完全对齐
- 更适合 `to agent` 的长周期托管与日志化体验

### 2. 入界登记如何进入战斗

- 所有战斗相关的注册修正必须基于 `registration_record v2` 的稳定 taxonomy IDs。
- `core_temperament` 决定基础战斗倾向，例如爆发、稳守、压制、续航、控场中的主偏向。
- `behavior_aspect` 决定起手和节奏倾向，例如先手抢节奏、后手反打、拉扯控位、站场推进。
- `cultivation_motive` 决定风险偏好与胜利收益倾向，例如更偏点杀、成长、保守或硬冲高压内容。
- `spirit_root_result` 与五行分数决定主元素与副元素，从而影响：
  - 元素法术强度
  - 元素状态强度
  - 元素抗性
- 注册收益必须保持为 `小幅加性修正`，影响手感与风格，不直接放大为跨层级碾压。

### 3. 首版属性与战斗面板落地

本节描述角色战斗面板的长期结构。当前 V1 仍保留这些面板字段，但本轮最小战斗结算不会消费全部详细属性。

- 战斗面板继续沿用既有 `8 个主属性 + 15 个详细属性 + 5 个五行属性` 三层结构。
- 八个主属性保持为：`根骨 / 体魄 / 灵元 / 神识 / 悟性 / 道心 / 身法 / 兵魄`。
- 十五个详细属性保持为：
  - `气血上限`
  - `灵力上限`
  - `灵力回复`
  - `外功伤害倍率`
  - `术法伤害倍率`
  - `命中`
  - `闪避`
  - `速度`
  - `韧性`
  - `控制强度`
  - `控制抗性`
  - `突破稳定`
  - `会心`
  - `暴伤`
  - `护心`

第一版冻结以下线性换算公式作为实现基线：

- `气血上限 = 100 + 4 × 体魄 + 2 × 根骨`
- `灵力上限 = 60 + 3 × 灵元 + 1 × 根骨`
- `灵力回复 = 2 + 0.04 × 灵元 + 0.02 × 道心`
- `外功伤害倍率 = 100% + 0.22 × 兵魄 + 0.08 × 体魄`
- `术法伤害倍率 = 100% + 0.22 × 灵元 + 0.08 × 神识`
- `命中 = 80 + 0.35 × 神识 + 0.15 × 兵魄`
- `闪避 = 5 + 0.25 × 身法 + 0.10 × 神识`
- `速度 = 100 + 0.30 × 身法 + 0.10 × 悟性`
- `韧性 = 0 + 0.20 × 体魄 + 0.10 × 道心`
- `控制强度 = 0 + 0.25 × 神识 + 0.10 × 悟性`
- `控制抗性 = 0 + 0.20 × 道心 + 0.10 × 体魄`
- `突破稳定 = 0 + 0.30 × 道心 + 0.15 × 根骨`
- `会心 = 0% + 0.10 × 身法 + 0.06 × 悟性`
- `暴伤 = 150% + 0.18 × 兵魄 + 0.06 × 灵元`
- `护心 = 0% + 0.15 × 道心 + 0.08 × 神识`

境界倍率仍然只直接作用于主属性，不直接作用于五行属性，也不直接放大外部加成。

### 4. 兵器与五行如何落地到战斗

本节描述完整战斗蓝图中的兵器与五行职责。当前 V1 默认只落地 `兵器` 通道的最小伤害模型，不要求本轮同时实现完整兵器家族与五行战斗结算。

- 继续遵循 `五行负责染色，兵器负责骨架`。
- 数据层保留 20 种兵器及其三属性适配关系。
- 首版可玩内容按 5 个兵器家族模板落地：
  - `快兵系`
  - `重兵系`
  - `长兵系`
  - `柔兵奇兵系`
  - `远奇灵兵系`
- 兵器适配统一采用既有权重：`主属性 50% / 副属性 30% / 辅属性 20%`。
- 第一版兵器只提供：
  - 1 个基础攻击模板
  - 1 个家族核心技模板
  - 1 个家族被动模板
- 五行状态继续沿用 `元素法术强度 / 元素状态强度 / 元素抗性` 的三层职责，其中：
  - `元素法术强度 = 本属性`
  - `元素状态强度 = 0.7 × 本属性 + 0.3 × 生我属性`
  - `元素抗性 = 0.7 × 本属性 + 0.3 × 克我属性`

### 5. 战斗结算框架

本节只保留当前 V1 真正要实现的战斗框架，并明确区分“动作层”和“路线层”。当前 V1 不再把旧的 `快攻 / 轻术`、`重招 / 大术`、`防御 / 调息` 当成现行约束。

- 单场战斗在一个 action job 内完成，内部按 world tick 推演战斗轮次。
- 当前正式冻结：`1 world tick = 1 战斗轮 = 30 秒`。
- 首版要求每个单位每个战斗轮最多行动 `1` 次。
- 死亡单位在当前轮立即失去后续行动资格，不允许出现“死亡后补动作”。

#### 5.1 当前 V1 的双层战斗模型

当前 V1 的战斗决策分成两层：

- `动作层`：决定“这一回合做什么”
- `路线层`：决定“这次伤害动作按什么风格打出去”

当前 V1 的动作层至少保留：

- `普通攻击`
- `核心技`
- `逃跑`

当前 V1 的路线层固定为：

- `蛮力`
- `巧劲`
- `战术`

其中：

- `普通攻击` 与 `核心技` 都属于伤害动作，必须绑定一条路线后才能进入伤害结算
- `逃跑` 属于非伤害动作，不进入三角克制伤害公式
- 当前 V1 不再把 `快攻 / 轻术`、`重招 / 大术`、`防御 / 调息` 写成现行必做动作层

#### 5.2 当前 V1 的单回合顺序

每个战斗轮固定按以下顺序推进：

1. 双方各自确定本回合动作
2. 若该动作属于伤害动作，则继续确定本回合路线
3. 计算双方先手值
4. 先手方先结算本回合动作
5. 若后手方已死亡，则本回合立即结束
6. 若后手方仍存活，则后手方再结算本回合动作
7. 写入本回合日志
8. 检查终局或进入下一 tick

当前 V1 的强约束是：

- 先手方先结算
- 先手方若已击杀后手，则后手本回合直接失去行动资格
- 不再使用“双方同步扣血”的极简结算模型

#### 5.3 当前 V1 的动作层

当前 V1 的动作层语义冻结如下：

- `普通攻击`
  - 默认稳定伤害动作
  - 作为零门槛基线动作存在
  - 当前动作倍率固定为 `1.0`
- `核心技`
  - 当前 V1 唯一保留的高价值主动伤害动作，非未来计划
  - 用于表达角色主力发力手段
  - 当前动作倍率固定为 `1.6`
  - 仅当 `currentSpirit >= coreSkillSpiritCost` 时可选
  - 当前资源成本冻结为：固定 `coreSkillSpiritCost`，由装备的具体装配配置表提供（参见 `docs/plans/2026-04-05-combat-gameplay-v2.md`，V2 装配层规则）
  - 灵力消耗在动作真正结算时扣除：命中与否都扣；若角色在出手前已死亡，则不扣
- `逃跑`
  - 当前 V1 的正式战斗动作，非未来扩展
  - 当前单人 PVE 只允许玩家侧选择
  - `mine-beast` 与 `guardian` 当前都允许玩家撤退
  - 成功时立即以“撤退战败”结束战斗，整体结果计为 `defeat`
  - 逃跑成功后保留当前的 `qi` 与剩余血量 (HP)
  - 失败时消耗本回合行动，不造成伤害


动作选择规则冻结为：

- 由服务器本地评分决定，不让 agent 参与逐 tick 选招
- 评分必须以稳定规则驱动，而不是中文标签字符串分支
- 动作层也必须吃注册的性格偏好，且当前只硬接：
  - `core_temperament`
  - `behavior_aspect`
- 动作层和路线层都吃注册偏好，但必须分开建表，不能直接复用同一组权重
- 当前 V1 只要求动作层稳定支持 `普通攻击 / 核心技 / 逃跑`，额外动作扩展延后

当前 V1 的动作评分公式冻结为：

`ActionScore = actionBaseWeight + registrationActionBias + battleStateBias + resourceBias + smallRandom`

其中：

- `registrationActionBias` 来自动作层专用的 `core_temperament + behavior_aspect` 权重表
- `registrationActionBias` 不得直接复用路线层的 `brute / finesse / tactic` 权重表
- **冻结动作层基准权重**:
  - `basic_attack = 0`
  - `core_skill = +1`
  - `escape = -4`
- **冻结动作层战场态势偏好 (battleStateBias)**:
  - 自身 HP 比例 <= 0.35: `basic_attack = 0`, `core_skill = -1`, `escape = +4`
  - 敌方 HP 比例 <= 0.25: `basic_attack = +1`, `core_skill = +2`, `escape = -3`
  - 战备度 (readiness) 为 `poor`: `escape = +2`
  - 战备度 为 `advantaged`: `core_skill = +1`, `escape = -1`
- **冻结资源偏好 (resourceBias)**:
  - `currentSpirit / maxSpirit >= 0.50`: `core_skill = +1`
  - `currentSpirit / maxSpirit <= 0.20`: `core_skill = -1`


#### 5.4 当前 V1 的路线层

路线层仍然是当前 V1 伤害差异的主骨架：

- `蛮力 -> 兵魄`
- `巧劲 -> 身法`
- `战术 -> 道心`

三角克制关系冻结为：

- `战术克蛮力`
- `蛮力克巧劲`
- `巧劲克战术`

克制倍率冻结为：

- 克制方：`1.15`
- 被克方：`0.90`
- 中性：`1.00`

路线附加修正冻结为：

- `蛮力`：`+8%` 最终伤害
- `巧劲`：`+8` 先手值，`+5` 闪避
- `战术`：`+5` 命中，`+4%` 会心

#### 5.5 当前 V1 的先手、命中与暴击

先手公式冻结为：

`先手值 = 速度 + 准备度修正 + 路线修正 + 小随机`

其中：

- `poor = -20`
- `stable = 0`
- `ready = +10`
- `advantaged = +20`
- `蛮力 = 0`
- `巧劲 = +8`
- `战术 = 0`
- `小随机 = 0 ~ 10`

当前 V1 不再保留：

- 上一回合影响下一回合的节奏链
- 伏击 / 被伏击
- 主动开战固定先手红利

命中率公式冻结为：

`命中率 = clamp(75% + (攻方命中修正后 - 守方闪避修正后) × 0.2%, 35%, 97%)`

其中：

- 攻方命中修正后 = `命中 + 路线命中修正`
- 守方闪避修正后 = `闪避 + 路线闪避修正`
- `巧劲` 提供 `+5` 闪避
- `战术` 提供 `+5` 命中

暴击率公式冻结为：

`暴击率 = clamp(攻方会心修正后 - 守方护心 × 0.7, 0%, 55%)`

其中：

- 攻方会心修正后 = `会心 + 路线会心修正`
- `战术` 提供 `+4%` 会心
- 当前 V1 不额外引入“技能基础会心”或“武器基础会心”层

暴击伤害倍率冻结为：

`暴击倍率 = 暴伤 / 100`

结算顺序冻结为：

- 先判命中
- 未命中则本次伤害为 `0`
- 命中后才进入暴击判定
- 暴击只会发生在命中之后

#### 5.6 当前 V1 的伤害结算

当前 V1 仍默认只走 `兵器` 通道，`法术` 通道只保留接口。

攻防底盘公式冻结为：

- `兵器攻击力 = 20 + 0.60 × 体魄`
- `法术攻击力 = 20 + 0.60 × 灵元`
- `物防 = 8 + 0.45 × 根骨`
- `法防 = 8 + 0.45 × 神识`

当前实际战斗只使用：

- 攻击端：`兵器攻击力`
- 防守端：`物防`

底盘伤害冻结为：

`底盘伤害 = max(1, 攻击力 - 防御力 × 0.5)`

三路线主属性系数冻结为：

- `三轴平均 = (兵魄 + 身法 + 道心) / 3`
- `蛮力系数 = 1 + clamp((兵魄 - 三轴平均) × 0.01, -0.15, 0.15)`
- `巧劲系数 = 1 + clamp((身法 - 三轴平均) × 0.01, -0.15, 0.15)`
- `战术系数 = 1 + clamp((道心 - 三轴平均) × 0.01, -0.15, 0.15)`

最终伤害公式冻结为：

`最终伤害 = 底盘伤害 × 动作倍率 × 路线主属性系数 × 克制系数 × 路线伤害修正 × 暴击修正`

其中：

- `普通攻击` 的动作倍率为 `1.0`
- `核心技` 的动作倍率为 `1.6`
- `蛮力` 的路线伤害修正为 `1.08`
- `巧劲 / 战术` 的路线伤害修正为 `1.00`
- 未暴击时 `暴击修正 = 1`
- 暴击时 `暴击修正 = 暴伤 / 100`

数值处理规则冻结为：

- miss 时 `finalDamage = 0`
- hit 后最小伤害为 `1`
- 全部乘区完成后统一取整为整数伤害

#### 5.7 当前 V1 的逃跑结算

`逃跑` 是当前 V1 的正式动作，不属于后续补丁动作。

逃跑成功率冻结为：

`escapeChance = clamp(35% + 速度差 × 0.2% + 劣势修正 + 准备度修正, 10%, 85%)`

其中：

- `速度差 = 逃跑方速度 - 追击方速度`
- `劣势修正` 当前冻结为：
  - `selfHpRatio <= 0.20` 时 `+20%`
  - `selfHpRatio <= 0.35` 时 `+10%`
  - 其余情况为 `0%`
- `准备度修正` 继续复用 `battleReadiness` 的四档修正（`poor=-20`, `stable=0`, `ready=+10`, `advantaged=+20`）


逃跑规则冻结为：

- 当前单人 PVE 只有玩家侧可以选择 `逃跑`
- 若后续接入 PvP，则双方都可能拥有 `逃跑`
- 逃跑成功：本场战斗立即结束，整体结果按 `战败` 处理，结束原因记为 `撤退`
- 逃跑失败：本回合行动被消耗，不造成伤害
- 逃跑不进入三角克制伤害公式
- 撤退不产出正常胜利奖励
- 撤退不会追加额外战败惩罚，角色保留撤退当下的当前 `qi` 与当前剩余血量
- `guardian` 遭遇当前也允许玩家撤退，但同样不提供战胜奖励

#### 5.8 注册层驱动的路线选择

当前 V1 的注册偏好会同时驱动 `动作层` 与 `路线层`，但两者必须使用不同权重表。本节只冻结 `路线层` 的规则，不覆盖动作层权重。

当前 V1 的路线选择不额外发明独立“人格系统”，而是直接复用注册层已有字段。

为控制复杂度，当前 V1 只硬接以下两个注册字段：

- `core_temperament`
- `behavior_aspect`

当前明确不接入：

- `secondary_temperament`
- `cultivation_motive`

当前 V1 的路线评分公式冻结为：

`StyleScore = staticBias + battleStateBias + smallRandom`

其中：

- `staticBias = registrationBias + attributeStyleBias`
- `registrationBias = coreTemperamentWeight + behaviorAspectWeight`
- `attributeStyleBias` 来自 `兵魄 / 身法 / 道心` 相对三轴平均值
- `battleStateBias` 只保留最小局内修正
- `smallRandom` 只用于避免完全同质化

采样方式冻结为：

- 先计算 `蛮力 / 巧劲 / 战术` 三条路线的 raw score
- 只保留前两名
- 对前两名做加权抽样

主 spec 只保留规则边界与合成公式；具体权重值继续由 `docs/specs/combat-gameplay-v1/registration-action-weight-table.md` 维护。

### 6. 标准状态库与首版落地子集

- 本节保留为后续扩展的状态库蓝图，不代表当前 V1 必须同步实装。
- 当前 V1 已明确延后 `控制 / 状态附着 / 五行战斗内结算`，因此本节内容只作为下一轮扩展的设计来源。
- 第一版完整标准状态库继续以 `docs/specs/oc-cultivation-foundation/five-element-status-and-skill-prototypes.md` 为来源。
- 当后续进入状态扩展阶段时，首个实现波次优先支持以下 10 个核心状态：
  - `裂甲`
  - `回春`
  - `缠绕`
  - `霜寒`
  - `冻结`
  - `焚灼`
  - `熔甲`
  - `岩甲`
  - `镇压`
  - `地壁`
- 其余标记、护体、场域扩展状态可在第二波复用同一底层继续补齐。

### 7. 内容入口与风险回报

- 战斗必须服务于 `游 / 居 / 遇 / 势` 的大循环：
  - `游`：提供野外区域、地形、怪物与危险探索
  - `居`：提供备战、恢复、炼丹、炼器与底牌生产
  - `遇`：提供单人精英与组队副本
  - `势`：提供宗门冲突与阵营对抗
- 首版强制支持的单人 PVE 内容：
  - 矿脉妖兽
  - 遗迹守关者
  - 一个可复用的精英目标模板
- 战斗胜利至少可以产生以下一种收益：
  - 区域材料
  - 灵石
  - 修为推进
  - 战斗相关短效状态
  - 对应系统声望或关系变化
- 战斗失败至少必须产生以下一种成本：
  - 气血 / 灵力损耗
  - `injured` 持续时间增加
  - 负面状态附着
  - 时间节奏中断
- 首版不做 PVP 装备爆落；高风险内容的惩罚优先以 `时间 / 状态 / 恢复成本` 呈现。

#### 7.1 首版战斗时长分层

为与 `1 tick = 30 秒` 的世界时间保持一致，首版战斗时长先按内容层级冻结为：

- `普通野外遭遇`：`1 - 3 ticks`
- `单人精英 / 守关者`：`4 - 8 ticks`
- `副本 Boss`：`8 - 20 ticks`
- `宗门 / 阵营高光冲突`：`20 - 40 ticks`

这意味着：

- 普通战斗仍然较短，不至于压垮世界日常循环
- 高价值内容可以自然拉长到 `10 - 20` 分钟，符合高压战斗体验
- 战斗时长差异主要来自内容层级，而不是临时拉高服务器结算频率

#### 7.2 与当前外循环节奏的兼容说明

当前世界层仍保留：

- 一次标准 `游历` 固定消耗 `10 ticks`

该值当前仍作为 `V1` 验证玩法节奏的测试基线保留。

后续如果为了匹配更激烈的战斗和更长事务体验，把 `游历` 拉长到 `60 ticks`，首版战斗的 tick 模型也不需要推翻，只需要整体重调动作时长和内容参数。

### 8. 四类战场与首版覆盖

首版战斗规格继续按 4 类战场统一建模，但分清“底层保留”与“首批硬做”的区别。

#### 8.1 野外遭遇战

定位：

- `游` 的基础风险战斗
- 单人 PVE 的最常见入口
- 用于把区域风险、地形差异与资源采集真正结算成成本与收益

典型来源：

- 矿脉妖兽
- 八荒巡猎妖兽
- 归墟节点守卫
- 野外随机精英

首版要求：

- 作为 `V1` 硬交付内容
- 必须能稳定接回区域材料、伤势、状态与日志

#### 8.2 精英守关战

定位：

- `游 + 遇` 的中压内容
- 比普通野外遭遇更强的单人 build 检验点
- 用于产出普通采集难以获得的高价值材料

典型来源：

- 遗迹守关者
- 悬赏邪修
- 州郡异变首领

首版要求：

- 作为 `V1` 硬交付内容
- 必须能复用同一回合结算底层，不另起 boss 专属系统

#### 8.3 组队副本战

定位：

- `遇` 的核心协作 PVE 战场
- 用于验证多角色 build 的互补性
- 用于承接更高收益、更长准备链的内容

首版要求：

- 不作为 `V1` 首批硬交付
- 但在数据与结算层必须复用与单人 PVE 同一底层
- 后续阶段可以在同一框架上增加 boss phase、多人分工与协作状态

#### 8.4 阵营 / 宗门战

定位：

- `势` 的高光冲突战场
- 用于承接宗门归属、同州对立与长期恩怨
- 用于提供强情绪和高传播时刻

首版要求：

- 不作为 `V1` 首批硬交付
- 先保留为同底层可复用的高级内容入口
- 后续优先做“异步结算 + 在线召集表现层”，而不是直接上重同步战场

### 9. 分波次落地

为了确保战斗系统真正可做，当前分波次路线冻结为：

- `V1`：矿脉妖兽、遗迹守关者、一个通用精英模板
- `V1.1`：组队副本 boss 模板
- `V1.2`：宗门 / 阵营战模板

各波次职责进一步解释如下：

#### 9.1 `V1`

- 先跑通单人 PVE 的统一规则战斗
- 验证动作层、路线层、先手、命中、暴击、逃跑与三角克制是否能在同一底层正确结算
- 验证战后回写、掉落、伤势与日志是否闭环

#### 9.2 `V1.1`

- 在不推翻底层的前提下加入多人协作战斗模板
- 增加队伍协作、Boss 压力与更长战斗链路
- 但仍尽量复用单人战斗已有的行为、状态和结算骨架

#### 9.3 `V1.2`

- 在异步底层之上叠加宗门 / 阵营的组织化冲突表达
- 先做“能被日志化、能被回写、能被展示”的高光冲突
- 同步体验、战场调度与更强对抗表现延后

## 当前阶段总结

### 1. `战` 在总玩法里的定位

当前已经明确：

- `战` 不是与 `游 / 居 / 遇 / 势` 平级的第五主板块
- `战` 是这四块之间的高风险结算层
- `战` 负责把探索风险、任务冲突、宗门事务与高压遭遇，结算成伤势、消耗、掉落、修为推进与日志回写

一句话总结：

> `战` 负责“打成什么结果”，而不是负责“玩家平时在哪生活、做什么循环”。

### 2. 当前已经冻结到可实现的部分

当前已经明确并可以直接指导实现的部分包括：

- `入口模型`：战斗必须通过 action 发起，不能脱离世界状态单独开打
- `执行模型`：单场战斗在一个 action job 内完成，内部按 `world tick` 推演战斗轮次
- `动作层`：当前 V1 至少保留 `普通攻击 / 核心技 / 逃跑`
- `路线层`：当前 V1 固定为 `蛮力 / 巧劲 / 战术`
- `路线映射`：`蛮力 -> 兵魄`，`巧劲 -> 身法`，`战术 -> 道心`
- `三角克制`：`战术克蛮力`、`蛮力克巧劲`、`巧劲克战术`
- `先手规则`：速度、准备度和路线修正进入同一先手公式，先手方先结算，击杀后后手失去行动
- `命中与暴击`：命中 / 闪避、会心 / 暴伤已进入当前 V1 正式结算
- `逃跑规则`：逃跑是当前 V1 的合法动作，不再被视为后续补丁
- `回合上限`：`hunt-mine-beast = 5`，`challenge-guardian = 7`
- `结果回写`：战后必须统一回写气血、灵力、伤势、奖励和战斗日志

### 3. 当前明确未进入本轮的部分

当前 spec 也已经明确，以下内容不属于本轮 V1 必做项：

- `控制 / 状态附着`
- `五行` 的战斗内结算
- `防御 / 调息`、`重招 / 大术` 等额外动作层扩展
- 完整 `18` 兵器细分与完整兵器家族技能树
- 组队副本细分协作逻辑
- 宗门 / 阵营 / PvP 的高阶战斗表达

### 4. 以现在的规格，能做什么，不能做什么

当前规格已经足够支撑：

- 一版按 world tick 推进的单人 PVE 战斗
- 一版明确区分动作层与路线层的回合结构
- 一版包含先手、命中、暴击、逃跑与三角克制的轻量完整战斗

但当前规格还不足以直接支撑：

- 更复杂的动作树与资源博弈
- 控制链与元素状态联动
- 完整兵器家族深度 build
- 多人副本、宗门大战和赛季化 PvP

### 5. 下一轮最该定的内容

如果接下来继续补 `战`，最建议按以下顺序推进：

1. `普通攻击 / 核心技 / 逃跑` 的精确动作评分规则
2. 各兵器家族如何影响 `核心技` 模板
3. 敌人模板与精英模板
4. 逃跑中的“劣势修正”参数
5. 奖励和失败成本参数表

这样做可以保证：

- 先把当前 V1 的动作层真正定死
- 再补内容模板
- 最后再进入控制、状态和更复杂的扩展层

## Acceptance Criteria

- 仓库内存在一份明确说明首版战斗如何整合 `registration / attributes / weapons / realms` 的 change-specific spec。

- 文档明确规定当前 V1 的路线层固定为 `蛮力 / 巧劲 / 战术`，并给出三角克制关系。
