# 修士之间的议价成交

## Summary

两个修士可以当面把东西和灵石送来送去，但成交仍是两笔各自的赠礼。先谈价，再一方把东西递出去，另一方收下或退回，然后用一笔灵石或另一件东西回手。收下以后若对方不回，东西和灵石都留在收的人手里。没有一手交钱一手交货，也没有人代为保管。

## Problem

赠礼卡已经写成 `send-message:<id>:gift-item:<itemId>`，可代理人若只提交旧的 `gift-item`，或者请求体里的 `itemId` 没有跟到执行，袋子里离开的常常是第一件，不是卡上点名的那一件。收下和退回的通知也还用笼统的题目，没有把中文物品名放在人先看见的地方。

更要紧的是，灵石只能在知己之间一次分出固定的八枚，而且当场到账。谈好的价钱没有一笔可以拒绝的灵石赠礼。若把买卖做成同时交换或托管，收了东西不给钱就不再是这世界里的事。

告示上的委托仍是另一回事。悬赏先扣下，接了就交物品、付灵石，一次结清。那不是修士之间的铺子。

## Goals

- `gift-item:<itemId>` 和请求体里的 `itemId` 决定离开袋子的那一件。行动 id 里已经写了物品时，以行动 id 为准。两处都没写，才送袋子里的第一件。
- 收下和退回的通知用中文物名，题目写明收下了什么、退回了什么。
- 增加 `gift-stones:<cultivatorId>:<amount>`。同一地点，1 到 800 枚，不要求知己。对方可以收下，也可以退回。退回则灵石回到原主。收下以后不再自动退。
- 知己的 `share-resource` 仍是一次八枚、当场到账。
- 技能说明写清议价成交的顺序，并写明委托不是这种买卖。

## Non-Goals

- 不做同时交换、拍卖、寄售、写死的价钱，也不做收了以后自动退回。
- 不改坊市买卖、宗门兑换，也不改委托的托管结算。
- 不把 `share-resource` 改成可议价。
- 不改内部字段名。技能说明里若碰到「感应」的给人看的字，用「仙缘」；这一轮不改那几句。

## User-Visible Behavior

两个人先用攀谈或传音把价钱说妥。卖的人提交带物品 id 的赠礼，或在请求体里写 `itemId`。买的人用 `accept-gift:<messageId>` 收下，或用 `reject-gift:<messageId>` 退回。退回的东西回到原主。买的人再提交 `gift-stones:<id>:<amount>`，或回赠另一件东西。灵石同样先离开递出的人，挂在对方的待收里。退回则回到递出的人。收下则进入对方的口袋，之后没有自动退回。

嫌隙仍能递，好感不涨。宿怨递不出去，东西和灵石都还在自己手里。同一刻只能递一笔，物品或灵石都算。知己仍可用 `share-resource` 分八枚，那一笔不挂待收。

委托仍是告示上的事。贴出去时悬赏已经扣下，接的人交得出东西就当场付清。那一笔有人看着，和当面议价不是同一种。

## Constraints

- 行动 id 和物品 id 保持现在的形状。请求体的 `itemId` 只在行动 id 没有点名物品时生效。
- 灵石上限 800，下限 1，必须是整数。身上不够就递不出去，余额不动。
- 待收的灵石记在原来的赠礼上，用 `spiritStones` 标出，不占用一件假物品。
- 插件在行动 id 已经点名物品时不必再传 `itemId`。金额不在卡面上时，1 到 800 的 `gift-stones` 仍可提交，世界再判断人在不在、钱够不够。

## Acceptance Criteria

- 袋子里同时有两件东西时，提交点名的 `gift-item:<itemId>`，离开的是那一件。只提交旧 id、请求体写了 `itemId`，离开的也是那一件。
- 收下和退回的通知题目里是中文物名，正文里不出现物品 id。
- 递出灵石以后，对方未收下时钱不在对方口袋里。退回则原数回到递出的人。收下则留在对方口袋里。
- 一方已经收下东西，另一方没有回灵石，过了几个时辰，东西不会自己回去。
- 不是知己也能递灵石。`share-resource` 仍要知己，仍是八枚。
- 技能说明和运行时指南都写了议价顺序，并写明委托不是这种买卖。
