# Remaining Work Roadmap v1

## Summary

本规范汇总 Immortal Claw 项目从当前状态到"可全量游玩"之间所有未完成工作，按优先级和依赖关系组织为可执行的阶段性路线图。旧六区系统清理已基本完成（仅剩必要迁移/测试代码），当前瓶颈已转移到 P0 信息层修复和 P2 功能启动。

## Problem

项目 P1 核心循环约 70% 完成，机制层可运转但信息层冲突导致 Agent 决策不可靠。P2/P3 功能均未启动。缺乏一份统一的剩余工作清单来指导后续开发优先级。

## Goals

- 建立从当前到 P3 闭环的完整剩余工作清单
- 明确每项工作的优先级、依赖关系和验收标准
- 为后续实施提供阶段性把控依据

## Non-Goals

- 不重新设计已完成的系统
- 不扩展 P3 之外的新功能范围
- 本 spec 不替代各功能的独立 spec（大功能仍需单独写 spec）

## Constraints

- 遵循已冻结的 P1/P2/P3 scope-freeze 文档
- P2 必须在 P0 修复完成后启动
- P3 必须在 P2 闭环后启动
- 每项工作的实施仍需遵循 spec-driven-development 流程

## Phase 0：信息层修复（阻塞项，最高优先级）

P0 修复是 Agent 可靠游玩和 P2 启动的前提条件。

### P0-1 决策面统一

- **问题**：`onboarding`、`nextAction`、`agentGuidance.suggestedActions` 与实际可用行动列表互相矛盾
- **范围**：统一三个决策面输出，确保任何情况下建议行动 ⊆ 可用行动
- **验收**：给定任意世界状态，三个接口推荐的行动均存在于 `availableActions` 中
- **依赖**：无
- **现有 spec**：`agent-onboarding-autonomy/`（部分相关）

### P0-2 运行时词汇对齐

- **问题**：Agent 指南用"market"等旧名称，运行时暴露 `travel-to:qingzhou:main-city` 格式
- **范围**：Agent 指南、README、OpenClaw 插件描述全部对齐到运行时实际的九州 + LocationId 命名
- **验收**：`public-copy-cleanup.test.ts` 扩展覆盖 Agent 指南，grep 无旧六区名称
- **依赖**：无

### P0-3 战斗日志清晰化

- **问题**：战斗日志 `damageTaken: 0` 但角色实际受伤/中毒，无法理解代价
- **范围**：战斗日志结构增加实际伤害明细（HP 变化、状态变化、灵力消耗）
- **验收**：每条战斗日志包含 `hpDelta`、`statusChanges` 且与角色实际状态一致
- **依赖**：无

### P0-4 恢复路径安全化

- **问题**：受伤/中毒后可能在无效恢复行动上循环浪费大量刻数
- **范围**：引导系统在中毒时强推解毒行动，受伤时推最高效恢复；无效恢复行动需标记警告
- **验收**：中毒状态下 `agentGuidance` 第一条推荐为解毒相关行动
- **依赖**：P0-1（决策面统一后才能可靠推送）

## Phase 1 收尾：体验打磨（P0 完成后）

P1 机制已实现，以下为体验层补全。

### P1-R1 居所概念清晰化

- **问题**：居所感觉像功能菜单而非世界中的地方
- **范围**：居所加入地点描述、环境事件、时间感知，使其有空间归属感
- **验收**：居所状态视图包含地点描述；居所内可触发至少 2 种环境事件

### P1-R2 任务 ActionId 可读化

- **问题**：任务行动 ID 为超长机器字符串，每次刷新变化
- **范围**：任务 ActionId 改为 `quest:{questType}:{index}` 格式，稳定且可读
- **验收**：所有 quest 类 ActionId 匹配 `quest:*` 模式，Agent 可按模式匹配选择

### P1-R3 引导系统上下文感知增强

- **问题**：引导过于通用，不针对当前情境
- **范围**：增加情境触发器（低血量、高价值物品、突破准备就绪等），引导内容动态化
- **验收**：至少 5 种情境下 guidance 给出差异化建议

### P1-R4 事件信号质量提升

- **问题**：旅行事件过于频繁，部分为无决策影响的噪音
- **范围**：区分"风味事件"和"决策事件"，降低风味事件频率，提升决策事件比重
- **验收**：决策事件占比 ≥ 40%；风味事件单次旅行不超过 2 条

### P1-R5 经济转化链可视化

- **问题**：获取资源时看不到完整转化链
- **范围**：获取资源时日志展示该资源的用途和转化路径
- **验收**：每种可转化资源的获取日志包含 `usableFor` 字段

## Phase 2：高风险深度循环（P1 收尾后启动）

遵循 P2 scope-freeze 的 6 个工作包序列。

### P2-0 遗留清理收尾

> 注意：大部分已完成。此阶段仅覆盖可能遗漏的边缘清理。

- 验证所有 Agent 指南/README 无旧六区描述（P0-2 已覆盖大部分）
- 清理 `startingPath` 软弃用最终移除
- 确认无死代码残留
- **验收**：`architecture-boundary-docs.test.ts` + `public-copy-cleanup.test.ts` 全绿

### P2-1 高风险内容强化

- **内容**：州特色精英 Boss、遗迹守卫、高风险后果机制
- **依赖**：游玩边界重置（P2-1a）
- **子任务**：
  - P2-1a 游玩边界重置：清晰区分荒野（资源）/ 秘境（进阶）/ 八荒（远征），各有独立入口节点
  - P2-1b 增强状态/状态力学：州特色事件联锁、多轮效果、恢复权衡
  - P2-1c 事件池对齐：全州特色风味、突破材料事件、事件库拆分
- **现有 spec**：`dungeon-event-pool-alignment-v1/`、`jiuzhou-state-event-flavor-v1/`、`breakthrough-material-event-support-v1/`

### P2-2 生产队列进阶

- **内容**：多配方队列、专精化、材料短缺处理
- **依赖**：P2-1
- **验收**：单角色可同时排列 ≥ 2 配方；材料不足时队列暂停并通知

### P2-3 基础私人社交 & Agent 通信

- **内容**：直接消息扩展、轻协作任务、关系追踪
- **依赖**：P2-1
- **现有 spec**：`private-agent-messaging/`
- **验收**：两个 Agent 可完成一轮消息交换 + 一个协作任务

### P2-4 Hooks 集成

- **内容**：事件/行动 hook 系统，支持外部集成和自动化响应
- **依赖**：P2-3
- **验收**：至少支持 3 类 hook（行动前/行动后/刻结束）

### P2-5 团队秘境 & 八荒评估

- **内容**：
  - 多人秘境探索：编队进入、协调行动、战利品分配
  - 八荒远征完整度评估（为 P3 做准备）
- **依赖**：P2-4
- **现有 spec**：`dungeon-expedition-v1/`、`dungeon-rank-expansion-v1/`、`dungeon-overlay-content-fill-v1/`
- **验收**：2-4 人编队可完成一次完整秘境探索循环

### P2 贯穿项

以下功能贯穿 P2 多个工作包，持续迭代：

| 功能 | 涉及工作包 | 现有 spec |
|------|-----------|----------|
| 战斗 V2（装配层 + 武器家族 + 法术扩展） | P2-1 ~ P2-5 | `combat-weapon-family-v2/`、`combat-loadout-sourcing-v2/`、`combat-lightweight-spell-status-v2/` |
| 物品目录 V2 统一 | P2-1 ~ P2-3 | `item-catalog-v2-unification/` |
| 开放式地点内容注册器 | P2-1 ~ P2-2 | `open-ended-location-content-v1/` |
| 秘境循环改进 | P2-1, P2-5 | `regional-dungeon-travel-pool-expansion-v1/` |

## Phase 3：终局与组织亮点（P2 闭环后启动）

遵循 P3 scope-freeze 的 6 个工作包序列。

### P3-0 P2 闭环门

- 验证 P2 所有工作包完成标记已达成
- 验证 P2 引入的系统测试覆盖 ≥ 80%

### P3-1 八荒完整化

- 区域结构、门票/生存机制、极端事件、稀有奖励、撤退压力系统

### P3-2 归墟完整集成

- 多阶段合作 Boss、共享世界进度、源心机制、终极法宝

### P3-3 多人组队战斗完善

- 编队机制、协调回合、团队 Buff/Debuff、战利品分配规则

### P3-4 帮派战争 & 门派等级

- 战争阶段、领地控制、帮派奖励、同盟系统
- 门派等级晋升、总部发展、旗舰能力

### P3-5 社交/战斗终局增强 + 最终闭环

- 多轮对话序列、声望等级、联合任务
- 全系统集成测试 + 闭环验证

### P3 闭环标准（来自 P3 closure-criteria）

1. 八荒可独立远征，有完整压力/奖励循环
2. 归墟可进入，有多阶段 Boss 和共享进度
3. 多人战斗可协调回合
4. 帮派可发动战争并争夺领地
5. 门派有等级体系和晋升路径
