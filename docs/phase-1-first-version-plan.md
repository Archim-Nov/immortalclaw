# 仙域项目计划一：首版

## 目标

首版不是做“大而全修仙 MMO”，而是做一个可以持续推进、可以接代理、可以验证玩法闭环的最小世界内核。

核心目标：

- 把世界状态从纯文档变成可执行模型
- 把动作从“描述”变成“规则 + 结算”
- 把长时行为从即时执行改成 job + tick
- 为后续接入 `OpenClaw` 预留稳定工具接口

## 首版范围

### 世界范围

- 3 个境界阶段：炼气、筑基、金丹
- 6 个区域：凡人城镇、修仙坊市、宗门山门、灵脉矿洞、秘境遗迹、疗伤圣地
- 1 个示例宗门
- 1 个示例修士
- 2 个基础物品：疗伤丹、回气丹

### 玩法范围

- 移动
- 闭关修炼
- 打坐恢复
- 疗伤闭关
- 凡间任务
- 灵矿采集
- 秘境寻缘
- 购买丹药
- 使用丹药
- 加入宗门
- 简化天劫
- 道心日志记录

### 技术范围

- TypeScript
- 单进程内存态世界
- HTTP API
- 不接数据库
- 不接 OpenClaw
- 不接前端

## 不做什么

- 不做多用户并发持久化
- 不做完整 PvP
- 不做道侣
- 不做炼丹炼器生产链
- 不做宗门占领战
- 不做魔道体系
- 不做 LLM 驱动大规模 NPC

## 首版架构

### 模块划分

- `packages/domain`
  - 世界状态
  - 规则结算
  - tick 推进
  - 动作可用性判断
- `apps/world-api`
  - HTTP 路由
  - 请求校验
  - 首版演示接口

### 状态模型

- `cultivators`
- `sects`
- `zones`
- `jobs`
- `messages`
- `daoLogs`

## API 目标

首版对齐设计稿，但只实现核心闭环：

- `GET /cultivator/state`
- `GET /cultivator/actions`
- `POST /cultivator/act`
- `GET /cultivator/messages`
- `GET /cultivator/tribulation`
- `GET /cultivator/sect`
- `GET /cultivator/dao-heart`
- `POST /world/tick`

## 里程碑

### M1 世界骨架

- 定义修士、区域、宗门、物品、job 数据结构
- 生成种子世界
- 完成状态读取接口

### M2 行动结算

- 接入动作列表
- 接入即时动作
- 接入长时动作和 tick 推进

### M3 系统闭环

- 加入简化天劫
- 加入道心日志
- 加入宗门信息和消息信息

### M4 可演示

- 可以通过 HTTP 走完整流程
- 有最小测试
- 有清晰文档

## 验收标准

- 可以启动服务
- 可以读取修士状态
- 可以查询当前可执行动作
- 可以发起长时动作并通过 tick 完成
- 可以看到修为、气血、灵力、灵石、日志的变化
- 可以在条件满足时看到天劫信息和结算结果

## 首版结束后的升级条件

只有当下面几点稳定后，才进入增强版：

- 动作设计基本合理
- tick 模型不需要推翻
- 道心日志粒度合理
- API 形状足够稳定
- 规则层和文本层已经分离
