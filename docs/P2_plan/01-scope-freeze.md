# P2 范围冻结

## 目标

P2 的任务不是重新定义 Immortal Claw，而是在 `P1` 已冻结的日常循环之上，补出一条更完整的高风险成长支路。

一句话定义：

> 在先完成旧壳清理的前提下，让玩家从 `九州日常循环` 稳定进入 `高风险准备 -> 单人精英 / 高风险遭遇 -> 回洞府生产与恢复 -> 宗门贡献排序与更强挑战入口` 的第二阶段循环。

这句话里最重要的点有两个：

1. `P2` 不是另起一套玩法世界。
2. `P2` 不是把所有后续想法一起塞进来，而是把 `P1` 的骨架继续往“更高风险、更强回报、更长准备链”推进。

## P2 与 P1 的关系

`P1` 已经冻结的主循环是：

`注册 -> 州主城落地 -> 低风险任务 / 州外游历 -> 回洞府恢复或转化 -> 更高收益任务 -> 加入宗门 -> 宗门任务与贡献 -> 周期性头衔更新`

因此 `P2` 的职责不是改写这条主循环，而是回答下面三个问题：

1. 玩家在 `P1` 跑稳之后，如何进入更高风险、更高收益的成长内容。
2. 洞府内循环如何从“基础生产”升级到“有准备链和等待成本的生产队列”。
3. 宗门与战斗如何在不膨胀成大系统的前提下，给高风险内容提供更强的长期目标。

简单说：

- `P1` 解决的是“这个世界能不能活起来”。
- `P2` 解决的是“这个世界活起来以后，玩家为什么继续往更深处走”。

## P2 启动前提

`P2` 不应直接建立在已确认的污染项之上。

因此本阶段默认前提是：

- 先执行 `00-deletion-cleanup.md` 中的清理计划
- 不再让 `天劫 / 雷劫 / tribulation` 继续参与当前流程判断
- 不再让旧 `six-zone world` 壳继续充当对外世界模型
- 不再把旧 `healing-sanctuary` 医馆口径当成恢复主流程
- 不再把 `townsfolk / market-guild / rogue-cultivators` 当成长期正式势力字段
- 不再在计划与设计稿中引入 `剑修 / 丹修 / 阵修` 式宗门分类
- 宗门阵营统一使用 `正道 / 魔道 / 中立`，其中 `中立` 只用于九大默认宗门

这里的原因很简单：

如果 `P2` 直接叠在这些旧壳上，新的高风险内容、事件层和宗门层就会继续被旧世界表达带偏。

## P2 的核心方向

### 1. 从 `P1 日常循环` 升级到 `高风险成长循环`

`gameplay-build-foundation` 与 `combat-gameplay-v1` 的共同指向都很明确：

- `P1` 先做九州日常可玩循环
- `P2` 再把高风险探索、单人精英和更长准备链接上来

因此 `P2` 的第一主方向冻结为：

- 强化 `州内高风险入口`
- 强化 `单人精英 / 守关者 / 强遭遇模板`
- 让 `遇 -> 战 -> 居` 这条支路从“能跑”升级到“值得反复跑”

这意味着：

- `P2` 的战斗扩展要优先服务 `单人 PVE` 与 `高风险节点`
- 不应一上来就跳到大规模多人玩法或大型组织对抗
- 高风险内容必须继续服从 `action -> tick -> log`，而不是变成独立副本大厅

### 2. 把洞府从 `基础生产` 升级到 `生产队列`

`P1_plan` 已明确保留基础生产，但故意没有把它扩成大系统。

因此 `P2` 的第二主方向冻结为：

- 在 `居` 模块中引入真正的 `queued production`
- 让洞府承担更清晰的备战、补给、恢复和中期投资职责
- 把“带回材料 -> 安排生产 -> 等待完成 -> 带着底牌再出门”做成真正成立的循环

这里的设计原则是：

- 做 `生产队列`
- 不做 `洞府经营模拟器`
- 做 `备战链`
- 不做 `大型内政系统`

对非技术视角来说，可以把它理解成：

`P1` 的基础生产更像“立刻做个补给”，`P2` 的生产队列则像“排产和备货”，会开始影响你下一次远征的准备节奏。

### 3. 基础私域社交与 agent 交流进入 `P2`，但只做轻扩展

`P1` 已经明确保留 `好友交流` 作为洞府中的轻社交入口。

同时，`gameplay-build-foundation` 也已经把边界写清楚了：

- `P1` 做好友交流
- `P1` 不做完整道侣系统
- `P1` 不做完整仇人系统

因此 `P2` 在社交上的合理升级方向冻结为：

- 把 `好友交流` 从单点动作升级成 `基础私域社交层`
- 让已建立关系的角色 / agent 之间，能发生 `消息 / 轻互助 / 轻委托 / 串门 / 照应`
- 让这些社交结果真正影响 `social-log`、推荐动作、准备度和后续钩子

这里可以允许的扩展包括：

- `好友` 关系继续存在并更有作用
- 增加轻量的 `道侣倾向` 或 `仇怨` 标签
- 让关系变化开始挂接到任务、宗门、赶路消息和洞府内循环

这里明确不做的内容包括：

- 完整道侣系统
- 完整仇人追杀链
- 大型婚恋模拟
- 独立社交大厅
- 脱离主循环的 agent 聊天系统

简单说：

- `P2` 可以让社交真正有一点重量
- 但不能让它膨胀成独立主玩法

### 4. 让事件池从 `统一九州基础池` 进入 `高风险覆盖层`

`event-pool-foundation` 现在冻结的是：

- `P1` 先把九州凡尘中的统一事件池骨架搭起来
- 八荒、归墟、宗门专属完整事件池后移

因此 `P2` 的第三主方向不应该是重写事件系统，而应该是：

- 在现有统一事件骨架上，增加高风险节点覆盖池
- 增加更强的 `encounterHook`
- 增加更清晰的 `followUpHooks`
- 让事件更自然地把玩家导向 `战斗 / 任务 / 宗门 / 交易 / 社交`

这里有一个重要边界：

- `P2` 继续复用统一事件框架
- 不为高风险内容另造第二套事件引擎

### 5. 宗门层进入 `轻量进阶`，而不是进入 `重经营`

`P1` 里的宗门定位已经很清楚：先做组织归属层。

结合 `gameplay-build-foundation` 的后续章节，`P2` 在 `势` 上最合理的升级方向冻结为：

- `贡献排序`
- `宗门专属事件覆盖`
- `更清晰的任务分层和推荐`
- `基础福利或资格差异`

不冻结为 `P2` 启动硬目标的内容包括：

- 宗门等级大系统
- 宗门经营
- 宗门建筑
- 宗门战争
- 阵营战高光版本

也就是说，`P2` 的宗门升级方向更像：

“让组织身份开始真正影响你做什么、能接什么、为什么继续做”

而不是：

“现在就做宗门模拟经营游戏”

### 6. 组队内容只做 `雏形验证`

`combat-gameplay-v1` 明确给出的顺序是：

- `V1` 先跑通单人 PVE
- `V1.1` 再接组队副本 Boss 模板
- `V1.2` 再接宗门 / 阵营战模板

因此 `P2` 对组队内容的冻结口径应是：

- 可以做 `组队副本雏形`
- 不能把 `多人深机制副本体系` 当成 P2 的主轴

更具体地说：

- P2 可以验证 `同底层战斗 + 多角色进入 + Boss 模板`
- P2 不需要一次做完多人职责分工、复杂 phase、完整掉落生态

### 7. 角色差异继续复用既有登记标签，不新造第二套分类

`combat-gameplay-v1/spec.md` 和 `registration-action-weight-table.md` 已经把一个关键口径写得很清楚：

- 首版战斗行为偏好继续复用 `core_temperament + behavior_aspect`
- 运行时继续依赖稳定 taxonomy IDs
- 不额外发明独立人格系统

因此 `P2` 的冻结方向也应保持一致：

- 可以扩展高风险内容
- 可以扩展敌人模板、Boss 模板、组队模板
- 但不应为了做 `P2`，重新发明新的职业标签、人格标签或战斗风格分类体系

简单说：

- `P2` 应该扩内容层
- 不应该重开一轮角色底层分类设计

## P2 对八荒的裁决

`gameplay-build-foundation/spec.md` 中和 `P2` 相关的表述有两个层次：

- 早期章节把 `P2` 写成：`高风险探索 + 基础生产队列 + 单人精英与组队副本雏形`
- 后续章节又把 `P2` 写成：`精英内容 + 八荒远征 + 生产队列 + 贡献排序 + 组队副本`

这两种说法并不需要互相打架，本文件统一裁决为：

- `P2` 可以触及 `八荒`
- 但这里的 `八荒` 只应指 `高风险远征入口 / 壳层 / 骨架`
- 不应理解成 `完整八荒系统已经成为 P2 启动前置`

因此当前冻结为：

- `P2` 若接入 `八荒`，应以 `高风险远征扩展层` 的身份进入
- 它必须建立在九州高风险循环已经成立的基础上
- 它不应反向吞掉 `P2` 的主体资源

简单说：

- `P2` 可以“摸到八荒”
- 但 `P2` 不应该“为了八荒而放弃先把九州高风险支路做扎实”

## P2 必做与不做

### P2 必做方向

- 清理已确认的旧机制污染，为 `P2` 建立干净起点
- 强化九州内的高风险入口、强遭遇和单人精英模板
- 把洞府基础生产升级为生产队列
- 把 `好友交流` 升级为基础私域社交与 agent 轻交流层
- 扩展统一事件池到高风险覆盖层和更强后续钩子
- 让宗门从“只有加入和做任务”升级到“贡献排序与更强组织差异”
- 以同一战斗底层验证组队副本雏形

### P2 暂不做

- 完整八荒世界层
- 归墟
- 宗门战争
- 阵营战高光版本
- 宗门等级大系统
- 宗门经营模拟
- 深度多人副本机制
- 完整道侣系统
- 完整仇人追杀链
- 独立大型社交系统
- 全新的职业 / 宗门分类体系
- 任何重新引入旧六区、旧医馆、旧城市场景势力壳的表达

## P2 的结构理解

从执行角度，当前最适合把 `P2` 理解成下面这条线：

`删除旧壳 -> 扎实九州高风险支路 -> 补洞府生产队列 -> 补基础私域社交与 agent 交流 -> 扩事件覆盖层 -> 补宗门轻进阶 -> 验证组队副本雏形 -> 再决定八荒扩展厚度`

这条顺序的好处是：

1. 先解决污染，再扩功能，避免旧壳继续拖偏实现。
2. 先把单人高风险循环做实，再上多人内容，避免底层没稳就堆复杂度。
3. 先让九州内循环变厚，再决定八荒做多深，避免版本主轴漂移。

## P2 验收方向

当 `P2` 走到可验收阶段时，至少应能回答下面这些问题：

1. 玩家是否已经有一条稳定的 `高风险准备 -> 挑战 -> 恢复 -> 再挑战` 循环。
2. 洞府生产是否已经从一次性补给，变成可排队、可等待、可规划的内循环。
3. 基础私域社交和 agent 交流是否已经开始真实影响消息、互助、关系连续性和推荐动作。
4. 事件是否已经能更自然地把玩家送进高风险内容，而不是只有平面掉落。
5. 宗门是否已经开始真实影响高风险内容的推荐、贡献排序和中期目标。
6. 组队副本是否已经在同一战斗底层上得到雏形验证。
7. 整个 `P2` 是否仍然保持在 `九州骨架 + 高风险成长扩展` 的范围内，而没有重新膨胀成另一套世界。

## 当前不冻结的内容

以下内容可以在后续 `02-feature-sequencing.md` 或专项 plan 中继续细化，但本文件暂不定死：

- `八荒` 到底在 `P2` 中占多大比重
- `组队副本` 的第一批模板数量
- `生产队列` 是先从炼丹还是先从炼器落地
- `贡献排序` 具体按什么周期刷新
- `高风险节点` 的首批具体命名和数值

也就是说：

- 本文件先冻结方向
- 不先冻结所有内容明细

## 当前冻结结论

- `P2` 的本质是 `高风险成长循环扩建`
- `P2` 必须建立在 `P1 日常循环已经成立` 的前提上
- `P2` 必须先执行旧壳清理，不允许带着污染继续扩写
- `P2` 的主轴是 `九州高风险支路 + 生产队列 + 基础私域社交 + 宗门轻进阶 + 组队雏形`
- `八荒` 在 `P2` 中只应作为高风险扩展层理解，不应吞掉主体方向
- `P2` 不做重宗门经营、不做完整阵营战、不做完整多人深机制副本，也不做完整道侣 / 仇人深系统
