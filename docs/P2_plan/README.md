# P2 规划总包

## 目的

本目录用于承接 `P1` 之后的第二阶段执行规划。

它的作用不是替代 `docs/specs/`，也不是推翻 `docs/P1_plan/` 已经冻结的执行口径，而是把 `P2` 真正要落地的内容整理成一组可执行、可拆分、可验收的规划文档。

当前 `P2` 的第一优先级不是继续往上叠新系统，而是先清理已经混入仓库、但不符合现行规划、并且会持续影响后续流程判断的旧设计。

## 使用原则

### 1. source of truth 顺序

P2 规划包默认按以下顺序解释冲突：

1. `docs/specs/clawcity-gameplay-alignment/spec.md`
2. `docs/specs/gameplay-build-foundation/spec.md`
3. `docs/specs/combat-gameplay-v1/spec.md`
4. `docs/P1_plan/`
5. 本目录中的 P2 细化规划文档

### 2. P2 与 P1 的关系

- `P2` 不是对 `P1` 重新开题
- `P2` 默认建立在 `P1` 的冻结边界已经成立的前提上
- 若当前仓库里仍存在与 `P1` 冻结口径直接冲突的旧机制，应优先进入删除 / 清理计划，而不是带着它们继续扩写 `P2`

### 3. 当前 P2 的启动原则

本目录当前采用以下启动口径：

- 先做 `删除计划`
- 再做 `P2` 新内容规划
- 删除计划只处理“明确不符合现行规划、且会持续影响世界流程/推荐/接口/前台表达”的旧设计
- 对于只是“尚未实现完毕”的 `P1` 内容，不纳入删除计划
- 对于已经在 `P1` / specs 中明确保留到后续阶段的系统，只有在它们错误进入当前运行流程时，才纳入清理范围

### 4. 本目录当前应优先处理的问题

在开始正式 `P2` 扩展之前，优先确认：

- 哪些旧系统已经变成公开接口或前台文案
- 哪些旧机制已经进入角色状态、推荐逻辑或行动判断
- 哪些兼容层仍在把世界模型拉回旧原型口径
- 哪些内容只是兼容残留，不应误删

- `03-social-agent-foundation.md`

## 后续维护规则

- 若某项内容与 `P1` 冻结结论冲突，先回到上层 spec 或 `P1_plan` 澄清，再写入本目录
- 若某项内容属于“旧机制清理”，优先补到 `00-deletion-cleanup.md`
- 若某项内容属于“P2 新增玩法”，优先补到对应的范围或排序文档
- 不把“删除计划”和“新增设计”混写在同一份正文里
