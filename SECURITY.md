# Reporting Security Issues

This early-stage project has no published response-time or supported-release commitment.

If GitHub displays **Security → Report a vulnerability**, use that private channel. If it is unavailable, open an issue asking the maintainers for a private reporting channel, without including vulnerability details, exploit steps, or affected credentials. Do not assume a private reporting channel is enabled.

In the private report, include the affected commit, runtime path, impact, and a minimal reproduction against a local instance you control. Redact bearer credentials, webhook secrets, user data, and environment files. Do not test against other people's worlds or bots without their permission.
