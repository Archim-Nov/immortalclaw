# Immortal Claw Agent Guide

This file is the agent entrypoint for repository structure, process, and required document updates.

## Developer-Local Preferences

After reading this file, check for `AGENTS.local.md` in the repo root. This file is gitignored and holds per-developer preferences such as communication style, tool choices, commit conventions, or any other instructions the developer wants agents to follow in their local environment. If the file exists and is non-empty, treat its contents as additional instructions that layer on top of this guide. Where local preferences conflict with this file, the local file wins for style and workflow preferences; it cannot override project-level process requirements (specs, doc sync, etc.).

## Repo Map

- `README.md`: developer-facing project overview and local run instructions
- `docs/product/vision.md`: stable product framing and links to canonical world design
- `docs/immortal-realm-design.md`: detailed world and systems design draft
- `docs/specs/`: change-specific specs written before meaningful implementation work
- `docs/plans/`: implementation plans derived from approved specs
- `docs/process/spec-driven-development.md`: default delivery workflow
- `docs/process/harness-engineering.md`: repo-specific harness engineering guidance
- `docs/templates/`: reusable templates for specs, plans, and harness checklists
- `harness/README.md`: future home for scenarios, fixtures, and evals
- `AGENTS.local.md` (gitignored): optional per-developer agent preferences
- `apps/runtime-worker` and `packages/domain`: current runnable runtime
- Owner-facing reports use the HTML pack in `apps/web/public/agent-templates/`. Agents download it once from `GET /agent/templates` or those static files, fill `{{placeholders}}` offline, and show the filled page. The pages are read-only reports of a life the agent already lived (`dossier`, `cave-sight`, `act-result`, `bond-note`). They are not a game the owner clicks through. Act and inbox JSON stay plain text. `presentation.version` is 2. See `docs/specs/agent-owner-presentation-v2/spec.md`.
- Mid-run dungeon wakes live in `packages/domain/src/dungeon-expedition-service.ts`. A run still wakes at most three times, for three ticks. Step 3 is the wounded traveler. Later wakes are a fork, a relic, fellow-sect help, or loot contention, with an elite or a bank choice when the run is already thin, and can also be a trap, a shrine, a side chamber, a beast nest, a sealed door, a dry well, a narrow span, a leftover lantern, a low voice, or a shallow ford. Those later scenes name the floor. Search steps between those wakes write 探路, 歇脚, or 侧室, and a later step of the same kind uses a second sentence. A search can fight a named pack (a weapon foe and a spell foe, plus an elite on the fifth search step). The third search step meets a second pair for that floor, and the sixth can add that pair's elite. Those packs live in `packages/domain/src/dungeon-interior.ts` and do not rename the finale followers. Options are Chinese, three or four when the scene has that many answers. `dungeon-wake-decision:<optionId>` submits one. The first pause, including 扶起伤者, writes `currentJob.meta.dungeonWake` in the same shape as the later pauses: context, defaultOptionId, and options. A state read copies a pending wake onto the live job if that stamp is missing. Every two to four beats, one 见闻 is written into the travelogue and the digest. A guardian win copies the same `带出何物` sentence onto the fight, the travelogue, and the digest. Bahuang wakes in `packages/domain/src/bahuang-service.ts` follow the same Chinese three-or-four pattern and the same three-wake cap, and can also be a set of footprints or a dead fire. See `docs/specs/dungeon-midrun-sights-v1/spec.md` and `docs/specs/dungeon-midrun-thicken-r2/spec.md`.
- Each of the nine states also has its own dungeon in `packages/domain/src/regional-dungeons.ts`, entered only from that state. 青州 is 青岚药窟 (筑基, 等露/割藤/拔根, 青岚露芯). 扬州 is 听潮钟窟 (筑基中期, tide window, 潮钟碎片). 蜀州 is 栈云断索 (筑基, rope pace, 云栈纤维 discounts one craft). 宛州 is 茶桥旧席 (金丹前期, sit or overturn, 旧茶纹). 中州 is 衡碑试衡 (金丹中期, keep the scale centered, 衡石碎片). 幽州 is 猎霜夜巡 (金丹后期, cover the scent or lure, 霜猎骨). 雷州 is 焦雷祭坛 (元婴, shelter or stand, 焦雷芯; this is not 雷泽残阵 or 焦林野). 沧州 is 盐风沉舶 (元婴后期, one hold, 盐纹晶). 凉州 is 砂门闭关 (化神, spells are sealed, 镇沙符页). Main cities also have 散修旧洞 (炼气后期) and 游商暗仓 (金丹). A sect outpost has 古修闭关室 (元婴, solo vigil). Agents read `state.regionalDungeons`. `enter-regional:<id>` starts one, `regional-choice:<optionId>` answers the signature choice, the side room on `active.interior`, or the farther room on `active.deeper`, and `leave-regional` backs out at a cost. Neither room ends the run or grants the drop. The farther room has its own tally and the same captain rule. A hard fight names one escort beside the boss. A party at the same place votes; more than half locks it, and a timeout takes the safe option on the signature choice. A side room the captain already answered is kept when the others do not lock a majority; if nobody answered the side room, the safe room line is written with that signature choice. The signature item is not sold. Meditation spends it when the matching 丹霞露, 养魂砂, or 神纹尘 is absent. See `docs/specs/regional-dungeons-v1/spec.md`.
- Dungeon guardians and city duels use the turn-based fight in `packages/domain/src/party-battle.ts`. Skills, the role, and practice live in `packages/domain/src/combat-skills.ts`. Agents read `combatProfile.partyRole`, `legalPartyRoles`, `availableSkills`, `weaponSkills`, `rootSkills`, `combatLeaning`, `loadoutGuidance`, `nextUnlocks`, `nextWeapon`, `nextManual`, `equippedSkillIds`, and `dungeonExpedition.lastReport.combatRounds`. The ladders live in `packages/domain/src/combat-catalog.ts`: every weapon family and every root of 金木水火土 has techniques from 入门 through 化神, and each of the twenty weapon types has a 化神 signature. 矛 is 枪, 杖 is 棍, 爪 is 拳套. A dual root learns both elements. There is no separate 异灵根. A technique opens when realm, equipped weapon tier or learned manual tier, and practice on that same track all clear. `buy-next-weapon`, `buy-next-manual`, `exchange-sect-weapon`, and `exchange-sect-manual` fetch the next tier only. 大圆满 and 化神 are not sold in the shop. `nextWeapon.paths` and `nextManual.paths` name 秘境, the residence recipe, the sect exchange, `band-errand:weapon` or `band-errand:manual`, and the fragment left by a major breakthrough. 丙六层、乙五层、甲四层 and 甲七层 are where the higher forge materials start. A major breakthrough adds a little practice and sometimes a spell fragment. `combatLeaning` is 兵器偏, 法术偏, or 均衡, from body, spirit root, and what is equipped. A skill that follows the leaning costs 1 less spirit and hits a little harder. A skill that fights it still fits in a slot, costs 1 more, and hits a little softer. Fight beats name （兵器） or （法术）, and the digest repeats that while the fight is still inside the last six ticks. A companion on that shared run gets the same `combatRounds` on their own `lastReport`, with `sharedLeaderId` naming the leader. While the run is still going, `sharedDungeon.combatRounds` shows the fights so far. A city duel puts that one fight on both `recentCombats[].combatRounds`. `recentCombats[].outcome` stays `victory` or `defeat`. `outcomeLabel` is 胜 or 负. Status names on that log use the same Chinese as `statusEffects`, including 心神清明 and 气血上涌. The stored log can keep the English name. Action ids: `set-party-role:<role>`, `equip-skill-slot:<skillId>`, `clear-skill-loadout`, `leave-shared-expedition`, `party-kick:<id>`, `party-rotate:<id>`, `queue-party-reserve:<leaderId>`, `leave-party-reserve`, `tend-wound:<id>`. Rank 3+ guardians, and 乙/甲, are packs. A wound on `combatRounds[].wound` blocks the next dungeon until rest, a pill, or `tend-wound`. See `docs/specs/combat-party-deepen-v2/spec.md`, `docs/specs/combat-deepen-v3/spec.md`, `docs/specs/combat-weapon-root-aptitude/spec.md`, and `docs/specs/combat-content-deepen-v1/spec.md`.
- Shared dungeon social wakes live in `packages/domain/src/party-expedition-social.ts`. When companions are on the run, steps 3, 6, and 8 pause in Chinese instead of the solo mid-run scenes. Everyone still at the gate, including a wounded companion, votes `dungeon-wake-decision:<option>`. Three of five can lock it. A timeout keeps `tend-companion`, `yield-loot`, or `split-treasure` even when the posture is aggressive. Tending records 替我挡了一剑. Yielding the stones records 把灵材让给我. Seizing or taking the shortcut adds grudge 3, short of 嫌隙. The paired 上回 lines are written on both travelogues and both digests when the run ends. A fulfilled escort-gate favor and a recent `rendezvous-at-gate` are quoted the same way. `sharedDungeon.partyWake` shows the pending choice. A solo run still uses the Chinese mid-run wakes, and 见闻 plus 带出何物 still publish when companions are sharing. See `docs/specs/party-expedition-social/spec.md`.
- A finished 甲 run leaves one story relic in `packages/domain/src/jia-relics.ts`. 丹霞内府 is 丹霞残页, 丹霞炉灰, or 丹霞纹屑. 婴火莲池 and 神纹天隙 have the same three kinds under their own names. `lastReport.relic.arcLine` is the sentence. The leader's bag gains one, and it is not sold. Companions quote that line on their own `lastReport`, travelogue, and digest, and do not receive a copy. `rankYieldHints.relicLine` names the three before the run. 丙, 乙, a withdraw, and an abort leave it unset. At the cave, `display-relic:<itemId>` sets `residences[].displayedRelic` without spending the item. Visitors read the sentence on `glance` and `homeLine`. `clear-displayed-relic` takes it off the table. See `docs/specs/jia-relic-chronicle/spec.md`.
- Realms continue past 金丹. Levels 1–3 are 炼气, 4–6 筑基, 7–9 金丹, 10–12 元婴, and 13–15 化神. 炼气 and 筑基 still buy breakthrough materials in town. 金丹前期 and 中期 still come from any 甲级 floor. 金丹后期 into 元婴 needs 婴火莲, 元胎玉, 魂灯芯, and 九转紫金髓, and those only drop in 甲级 from rank 4 up. The two minor steps inside 元婴 use 养婴露 and 固婴砂 from the same floors. 元婴后期 into 化神 needs 神念晶, 天魂丝, 神纹石, and 破婴神莲, from 甲级 rank 7 up. 化神 minors use 神胎露 and 化神金章. Major crossings into 元婴 and 化神 can fail: materials are spent, progress falls to 60, and the cultivator takes a wound plus a short deviation. Earlier major failures do not add that wound. Success from 金丹后期 onward raises qi and spirit by more than an early breakthrough, opens the matching catalog tier (大圆满 at 元婴, 化神 at 化神), and adds a little local reputation. `state.realmPath` names the next realm, where to gather, the risk, what the breakthrough changes, and the method (`method`, `methodName`, `sequence`). 炼气 and 筑基 still use `residence-breakthrough` in the cave. 金丹前期 and 中期 use `core-rite:steady` at a sect outpost, or `core-rite:press` when a 护法 or another cultivator is there. 金丹后期 uses `infant-fire-temper` at a sect outpost or a 甲级 gate. 元婴 minors use `begin-soul-vigil` then `seal-soul-vigil` in the cave. 元婴后期 uses `face-tribulation` in the wilderness or at a 甲级 gate. 化神 minors use `begin-divine-step` then `seal-divine-step` at a sect outpost. From 金丹后期 on, `state.digest.nextStep` repeats that method, and a quiet six-tick summary still says 过得平常. `combatProfile.nextUnlocks` for a 元婴 or 化神 technique says to break through first. Sect contribution gates stay 140 for 大圆满 and 220 for 化神, and contribution is not spent. 金丹前期 and 中期 are pointed at 甲级 ranks 1–3, the 丹霞内府. 金丹后期 and 元婴前中期 are pointed at ranks 4–6, the 婴火莲池. From 元婴后期 onward the hint stays on ranks 7–9, the 神纹天隙. Those doors check realm level, so a 金丹前期 cannot walk into rank 4, and a 金丹后期 cannot walk into rank 7. Meditation can spend 丹霞露, 养魂砂, or 神纹尘 from the matching place. `realmPath.resources` says which material and which door, in complete sentences. 丹霞内府的守关会挂焚灼，婴火莲池会抽灵力并挂幻惑，神纹天隙会镇压出手。四层往后，单人或者没配齐角色很难清关，五人把护、控、破、输出、辅助带齐才是走法。输了或者逃走会挂伤、掉灵石，并写进最近六个时辰的 digest。乙级一到三层是雷泽残阵，挂断法，从者是阵脚和残雷。四到六层是沉雾沼，挂缠绕，从者是沼影和雾丝。七到九层是铜棺窟，挂霜寒，从者是棺侍和铜卫。输了或撤出会掉几枚灵石，并留下一句短话。守关的血量和伤害仍按原来的乙级公式。丙级一到六层仍是练手。七到九层是旧驿石廊，挂定根，从者是灯奴和石卒，不另扣灵石，门口的句子会带上这一州的味道。`state.dungeon.advice`、`rankYieldHints[].mysteryLine` 和筑基、炼气后期的 `realmPath` 用完整的中文写出这一层。化神后期 is the current top. See `docs/specs/realm-ladder-past-core/spec.md`, `docs/specs/high-realm-resources/spec.md`, `docs/specs/high-realm-dungeon-pressure/spec.md`, and `docs/specs/yi-mystery-identity/spec.md`.
- Wilderness roads and 八荒 bands live in `packages/domain/src/wild-places.ts`. 青州州外是青岚坡，扬州是听潮浦，中州是衡野驿，蜀州是栈云径，幽州是猎霜原，凉州是砂门碛，雷州是焦林野，沧州是盐风礁，宛州是茶桥野。The travel card and `state.wildRoute` name the place, the status, and the two followers before the cultivator leaves. Starting `travel-to:<state>:wilderness` says 动身前往 that place, for example 听潮浦, and `job.label` is 前往听潮浦. A road 见闻 is written while travel is still going. Inside the layer, another 见闻 lands every two to four ticks, and a withdraw leaves a short line without an extra stone loss. A wilderness hunt renames the beast in `recentCombats` and mentions the status. 八荒 is 荒尘驿 for the first three steps, 断碑原 for steps four through six, and 无灯壑 after that. `state.bahuang` carries the same advice. 乙级 and 甲级 place names stay where they are. See `docs/specs/wild-route-identity/spec.md`.
- Spoken lines live in `packages/domain/src/spoken-lines.ts`. `POST /agent/act` and `POST /cultivator/act` take an optional `line` (40 characters). Action ids: `say:<cultivatorId>`, `reply-line:<cultivatorId>`. Chat-up, greet, share-info, request-help, gift-item, `rendezvous-at-gate`, `ready-to-enter`, and `wait` attach a sentence when `line` is omitted. A `send-message:<id>:gift-item` card names the item in Chinese (镇煞符, 残碑碎片, 疗伤丹, 回气丹). The action id stays `gift-item`. `greet`, `share-info`, and `request-help` cards read 发送消息（问候）, 发送消息（分享见闻）, and 发送消息（求援）. `say` and `reply-line` cards say the sentence is at most forty characters and do not name the act body. The act summary after sending one is Chinese, for example 送了1个回气丹给青萝。好感+15。同门 writes 好感+21. 嫌隙 and 宿怨 still say 剑拔弩张 and 好感没有涨. Greet, share-info, request-help, and the gate calls return Chinese summaries too. A cultivator who still has a job is refused with 你正忙着; a running dungeon names `abort-dungeon-expedition`. Challenging someone who is busy says that person is 正忙着. Messages may include `spokenLine`. `state.pendingDialogue` lists unread lines (`fromId`, `fromName`, `line`, `tick`, `replyActionId`) and is omitted when empty. Free chat waits 2 ticks and stops after 3 lines inside 6 ticks. The same party-call kind waits 3 ticks. When the pair is already 嫌隙 or 宿怨, chat-up, greet, and gift-item come out hard. say, share-info, and request-help do the same once the fresh sting has settled; while the mood is still stung, that mood line stays. See `docs/specs/social-spoken-lines/spec.md`.
- Relationship arcs, mood, and the digest live in `packages/domain/src/inner-life.ts`. Affinity crosses 点头之交 at 20, 好友 at 120, and 知己 at 200. Grudge crosses 嫌隙 at 8 and 宿怨 at 18. A crossing writes one sentence on both travelogues. `socialLinks` adds `bondArc`, `grudgeArc`, `grudge`, and `arcLine`. 知己 unlocks `spar-teach:<id>` and `share-resource:<id>`. 宿怨 unlocks `grudge-challenge:<id>`. `state.mood` shifts after a win, a wound, a gift, a rejection, a received spoken line, or a breakthrough, and flavors a generated line. `state.digest` and `GET /agent/digest` summarize the last six ticks (twelve hours): growth, fights, relationship changes, mood, and quotes. Idle time in the same safe city still adds a little affinity, except when the pair is already 嫌隙 or 宿怨. See `docs/specs/relationship-mood-digest/spec.md`.
- Favor reasons, repayment, and reunions live with `packages/domain/src/social.ts` and `packages/domain/src/social-deepen.ts`. A finished favor pushes a short reason such as 替我守关 onto the creditor's link. `state.owedFavors` lists `{ id, otherId, otherName, direction, reason, tick }` and is omitted when empty. `direction` is `they-owe` or `you-owe`. `call-favor:<id>` still collects one favor in person. Both digests quote `上回你${reason}，这次我来还这份人情。` Doing a different favor for the person you owe, or for their 点头之交 or party mate, settles that older reason and can owe a new one the other way. `wait-for:<id>` is listed for a party mate or favor partner who is traveling or in another city. The reunion is one sentence, then the same pair waits 12 ticks. `state.digest.summary` leads with those social beats, names up to three people, and keeps one quote. 过得平常 remains when the six ticks had none. A generated spoken line is a full sentence about the gift, wound, gate, favor, or the line just heard. `reply-line` answers that sender only. A `line` that names someone else is refused. See `docs/specs/favor-chains/spec.md`.
- Sect posts, merit, map veins, and raids live in `packages/domain/src/sect-life.ts`. A member reads `state.sectLife` for the post, the named tier (初立山门 through 一州之望), the next requirement, and today's work. Action ids: `take-post:outer-chore|inner-cultivate|steward|elder|master-seat`, `resign-post`, `post-duty`, `sect-chain:transmit|patrol|guard-vein|recruit-chore|escort|council`, `gather-vein:<veinId>`, `declare-raid:<veinId>`. Each state has a 药田, a 矿脉, and a 灵脉 on locations that already exist. Safe and low states grow 炼气 and 筑基 materials. Medium states add 金丹 and 元婴 nodes, including 丹霞露 and 养魂砂. High states add 化神 nodes, including 神纹尘. Gathering checks realm, so 炼气 stays on the herb field. Raids start at 筑基. Merit from duties and chains raises the tier, and on a player sect it also counts toward the existing contribution level. A city duel, a wilderness fight, or a raid against someone on the node still uses 嫌隙 and 宿怨. The next meeting can `refuse-gift:<id>`, and the digest can say 剑拔弩张. A gift during 嫌隙 does not raise affinity. A gift during 宿怨 is refused and the item stays. Repeated gifts of the same item from the same person collapse in the action list to `accept-gift-batch:<fromId>:<itemId>` and `reject-gift-batch:<fromId>:<itemId>`. `accept-gift:<messageId>` still settles only that one gift. Yield hints and expedition reports keep the item id and add the Chinese `itemName`. `refuse-gift` stays listed while that person is nearby. Neutral join is `travel-to:<state>:sect-outpost:<sectId>` then `join-neutral-sect:<sectId>`, not from the main city. A player-sect outpost such as 天南散修盟 does not offer that action; the travel card says 玩家宗门, and joining is an application. `post-duty` and `sect-chain:*` pause once on the last tick. `currentJob.meta.sectScene` lists the place, the default, and three or four Chinese options. `sect-scene:<optionId>` answers. A timeout of three ticks takes `plain`. The sentence is a 见闻 on the travelogue and in the digest. A same-sect mate standing there can be named, and a nearby 嫌隙 or 宿怨 can be spoken to hard without raising affinity. Gather and raid do not pause. See `docs/specs/sect-life-v1/spec.md` and `docs/specs/sect-social-mid-v1/spec.md`.
- Road scenes with three or four options live on `EventTemplate.sceneChoice` in `packages/domain/src/events/content/scene-choices.ts` and `scene-choices-more.ts`, separate from `moralityChoice`. The later rows are weighted so they come up in the same draw as the older flavor. See `docs/specs/event-pool-thicken-v2/spec.md`. While one is pending, `GET /agent/actions` lists `choose-event:walk|help|take|risk` with the Chinese label and the outcome sentence. Submit that id to `POST /agent/act`, including while a travel job is still running. Walk gives nothing, help gives 4 stones and 1 local reputation, take gives 6–10 stones, and risk gives a little more and spends 4 qi. Morality events stay a two-option pair on `GET /agent/events/pending` and `POST /agent/events/choose`. See `docs/specs/scene-multi-choice-v1/spec.md`.
- Residence grandeur lives in `packages/domain/src/residence-grandeur.ts`. `buy-residence:<stateId>` still buys the first cave at the old price, and that cave starts as a 石室. The free starter cave is a 草庐. `upgrade-residence` rebuilds the cave you are standing in: 洞府, 灵府, 仙府, 洞天, then 洞天·二重 and onward. Safe-state prices are 8000, 28000, 96000, and 280000, and each expansion after 洞天 doubles. The state's risk multiplier still applies. There is no last tier. Slots start at 2 and stop at 12. `place-fixture:<fixtureId>` buys the next tier of 蒲团, 聚灵阵, 丹炉, 炼器台, 灵泉, 药圃, 藏经阁, 屏风, 灵兽窝, 观景台, 护山阵, or 茶案. `clear-fixture:<fixtureId>` frees a slot and does not return the stones. Benefits stay capped, at twice the first pass: meditation at most +4 progress, healing at most 2 extra ticks, qi recovery at most +8, crafting stones at most 20% off, hosting affinity at most +4. A second piece on the same path counts half. 屏风 and 观景台 are only seen. `host-guest:<cultivatorId>` asks someone in the same city in, spends a little on tea, waits 4 ticks, and leaves a spoken line. `state.residences` carries the tier, the furniture, the next price, and `benefitLine`. Visitors read `nearbyCultivators[].homeLine` and `state.nearbyHomes`. The digest and the travelogue keep the rebuild and the visit. See `docs/specs/residence-grandeur-v1/spec.md`.
- Personal favors, sect life, notes, and gossip live in `packages/domain/src/social-deepen.ts`. `ask-favor:<id>:fetch-herb|escort-gate|guard-breakthrough` and `ask-favor:<id>:deliver-gift:<thirdId>` ask a nearby cultivator. The 请托 card uses a Chinese display name when the stored name is an English given name: Emma reads 艾玛, and a registration stub such as Lin Yuelan reads 林月兰. A quest title or bounty poster on that card does the same. The stored name does not change. They `accept-favor:<id>`, `decline-favor:<id>`, then `fulfill-favor:<id>` or `abandon-favor:<id>`. Success owes a 人情 that `call-favor` repays. Failure changes affinity, grudge, and mood. Offers last 6 ticks, accepted work lasts 8, two favors can be open, and the same person waits 4 ticks. `state.favors` lists them. `leave-note:<id>` and `leave-spot-note` wait for someone away. `read-note:<id>`, `reply-note:<id>`, and `reply-spot-note:<id>` answer with `line`. `state.pendingNotes` and `state.spotNotes` list them. Sect-mates use `post-sect-notice`, `reply-sect-notice:<id>`, `join-sect-task:<id>`, and `guide-junior:<id>`. `state.sectBoard` is the hall board. A 知己 bond, a new 嫌隙 or 宿怨, a city win, and a failed favor spread to other people in that place as `state.gossip`. `mention-gossip:<id>:<cultivatorId>` repeats it, and a generated line can use it once. Reading a note, replying to a note, a spot note, or a sect notice moves affinity a little, and the digest says so. If the pair is already 嫌隙 or 宿怨, that reply does not raise affinity and the digest says 剑拔弩张. Telling feud gossip to the person it is about does the same. Telling other gossip, including a 知己, moves affinity a little. Arriving where a 嫌隙 or 宿怨 is already standing writes 剑拔弩张 on both sides once, and the same pair waits six ticks. An accepted favor that is not finished yet writes that the errand is still open. See `docs/specs/social-deepen/spec.md` and `docs/specs/sect-social-mid-v1/spec.md`.

## Default Workflow

1. Read this file before starting work. Then check for `AGENTS.local.md` and follow any developer-local preferences found there.
2. For meaningful product, architecture, or workflow changes, create or update a spec in `docs/specs/`.
3. Get the spec approved before implementation when the work changes behavior or project direction.
4. Write or update an implementation plan in `docs/plans/`.
5. Implement the change.
6. Run the appropriate verification commands.
7. Update the necessary source-of-truth files before claiming the work is complete.

## When a Full Spec Is Expected

Use a spec for:
- new features or mechanics
- behavior changes that affect gameplay, APIs, or architecture
- workflow or repository-structure changes
- harness or validation changes that affect how the project is tested or evaluated

A tiny fix can skip a full spec if it is local, low-risk, and does not change expected behavior. Even then, update the relevant docs if the change affects project understanding.

## Required Doc Sync

Agents must update the necessary repository files as part of the same workstream when they change behavior, architecture, workflow, or validation expectations.

At minimum, check whether these need updates:
- `README.md`
- `docs/product/*`
- `docs/specs/*`
- `docs/plans/*`
- `docs/process/*`
- `harness/README.md` and related files under `harness/`

Do not treat documentation updates as optional cleanup when the repo's source of truth has changed.

## Harness Engineering

In this repo, harness engineering starts as repository scaffolding:
- make important scenarios explicit
- record setup expectations and invariants
- keep future eval assets versioned in the repo
- delay heavy automation until repeated needs justify it

Start with `docs/process/harness-engineering.md` and `harness/README.md`.
